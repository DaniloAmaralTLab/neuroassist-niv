# EDGE — API Contract

> Service: `edge-service` · Module **EDGE — Edge Device Integration** · Project: NeuroAssist NIV
> Stack: Java 21 / Spring Boot (hexagonal — `../../../adr/ADR-001-hexagonal-architecture.md`,
> key `hexagonal_java`) · Multi-tenant (schema-per-tenant) · Messaging disabled.
> EARS authoring guide: `../../../standards/ears-notation.md`.

EDGE plays **two security roles at once**. On its human-facing endpoints it is an **ACS resource
server** (it validates ACS-issued caregiver/coordinator JWTs via JWKS and issues no human token).
On its device-facing endpoints it is the **device authorization endpoint** (ADR-002 local): it
**mints** the `edge.device` token on a successful pairing claim, publishes its own JWKS so other
resource servers trust that token, and governs its immediate revocation. Tenant context on every
authenticated endpoint derives from the JWT `tenantId` claim (INV-EDGE-1); `X-Tenant-Id` is never
trusted.

---

## 0. Conventions

- **Base path:** `/edge`. GWY (API Gateway) fronts the service; paths below are as seen by the
  controller.
- **Media type:** `application/json`. Errors use `application/problem+json` (RFC 7807).
- **Identifiers:** all resource ids are UUID (string, canonical form).
- **Authority model:** fine-grained authorities follow `edge.<resource>.<action>`, sourced from the
  single `RoleAuthorityPolicy` (SPEC-06). Controller `@PreAuthorize` strings MUST equal those
  constants (INV-EDGE-7, D-535).
- **State-changing verbs** map to `POST` / `PATCH` / `DELETE` only (domain-framing convention);
  `GET` is side-effect free.

### 0.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `Authorization: Bearer <jwt>` | request | Required on every endpoint **except** `POST /edge/devices/pair` (code-authenticated), `GET /edge/.well-known/jwks.json` and `GET /edge/health` (public). |
| `X-Pairing-Code` | request | **Only** on `POST /edge/devices/pair`: the single-use bearer secret the station presents; not a JWT (§2.5). |
| `X-Correlation-Id` | request/response | Propagated end-to-end; generated by GWY if absent, echoed on the response and on every HIST audit call. |
| `X-Tenant-Id` | — | **Never trusted from the request.** Tenant context is derived from the JWT `tenantId` claim only (INV-EDGE-1). |
| `If-None-Match` | request | Optional on `GET /edge/catalog`; enables conditional `304` (§4.2). |
| `ETag` | response | Returned on `GET /edge/catalog` for device-side caching (ADR-004, §4.2). |

EARS — headers & auth:

- WHEN a protected EDGE endpoint receives a request without a valid `Authorization` bearer token, THE SYSTEM SHALL respond `401 Unauthorized`.
- IF a request supplies an `X-Tenant-Id` header, THEN THE SYSTEM SHALL ignore it and derive tenant context exclusively from the JWT `tenantId` claim (INV-EDGE-1).
- THE SYSTEM SHALL echo the received `X-Correlation-Id` on every response and on every downstream HIST audit call.

### 0.2 Token types consumed

| Token | Issuer | `actorType` | Used on | Validated via |
|---|---|---|---|---|
| caregiver / coordinator | ACS | `caregiver` | §2 human device-management endpoints | ACS JWKS (+ ACS introspect on sensitive ops) |
| `edge.device` | **EDGE** | `edge-device` | §3 (heartbeat), §4 (catalog) | EDGE JWKS (`/edge/.well-known/jwks.json`) + EDGE introspection on revoke-sensitive calls |
| service-client | ACS | `service-client` | §6 introspection consumers | ACS JWKS |
| pairing code | EDGE (minted on enroll) | — | §2.5 only | global `device_pairing_code` lookup (hashed) |

## 2. Device management (human endpoints — ACS resource server)

### 2.1 `POST /edge/devices` — enroll a device (authority `edge.device.enroll`)

A coordinator creates an `EdgeDevice` in `awaiting_claim` for a patient and EDGE mints a
**short-lived, single-use pairing code** (ADR-003). Anchor supporting action **DeviceEnrolled**.

Request:

```json
{ "patientId": "<uuid>" }
```

Response `201 Created` (+ `Location: /edge/devices/{id}`):

```json
{ "id": "<uuid>", "tenantId": "<uuid>", "patientId": "<uuid>",
  "lifecycleState": "awaiting_claim", "connectivity": null,
  "pairingCode": "WX7K-2Q9F", "pairingCodeExpiresAt": "2026-11-19T12:10:00Z",
  "enrolledBy": "<caregiverId>", "createdAt": "2026-11-19T12:00:00Z" }
```

EARS:

- WHEN a caller with `edge.device.enroll` enrolls a device for a patient of their tenant, THE SYSTEM SHALL create it `lifecycleState = awaiting_claim`, mint a single-use pairing code with a short `expiresAt`, respond `201 Created`, and audit `DeviceEnrolled` to HIST within the same request.
- THE SYSTEM SHALL set `tenantId` from the JWT claim and `enrolledBy` from the JWT `sub`, and SHALL ignore any tenant supplied in the body (INV-EDGE-1).
- THE SYSTEM SHALL return the plaintext `pairingCode` **exactly once** in this response and SHALL persist only its hash (INV-EDGE-3, Risk R2); subsequent reads never re-expose it.
- IF `patientId` is absent or malformed, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.

### 2.2 `GET /edge/devices` — list devices in tenant (authority `edge.device.read`)

Query: `?lifecycleState=awaiting_claim|paired|deactivated|revoked|all` (default `all`),
`?patientId=<uuid>` (optional). Response `200 OK`:

```json
{ "devices": [ { "id": "<uuid>", "patientId": "<uuid>", "lifecycleState": "paired",
  "connectivity": "online", "lastHeartbeatAt": "2026-11-19T12:09:30Z",
  "detectionState": "RUNNING", "detectionStateSince": "2026-11-19T12:05:00Z",
  "lastDetectingAt": "2026-11-19T12:09:30Z",
  "pairedAt": "2026-11-19T12:02:00Z" } ] }
```

- THE SYSTEM SHALL return only devices of the caller's tenant (INV-EDGE-1); cross-tenant rows are never disclosed.
- THE SYSTEM SHALL NOT include the pairing code or the credential secret in any list/read body (INV-EDGE-3, INV-EDGE-2).
- THE SYSTEM SHALL expose `detectionState`, `detectionStateSince` and `lastDetectingAt` on each row so a UI can show "station is NOT detecting" distinctly from "offline" (ADR-005, INV-EDGE-9).

### 2.3 `GET /edge/devices/{deviceId}` — read one device (authority `edge.device.read`)

Response `200 OK`:

```json
{ "id": "<uuid>", "tenantId": "<uuid>", "patientId": "<uuid>", "lifecycleState": "paired",
  "connectivity": "online", "lastHeartbeatAt": "2026-11-19T12:09:30Z",
  "detectionState": "RUNNING", "detectionStateSince": "2026-11-19T12:05:00Z",
  "detectionReason": null, "engineVersion": "1.4.2",
  "lastDetectingAt": "2026-11-19T12:09:30Z",
  "pairedAt": "2026-11-19T12:02:00Z", "enrolledBy": "<caregiverId>",
  "credentialId": "<kid/jti>", "catalogFetchedAt": "2026-11-19T12:08:00Z",
  "createdAt": "2026-11-19T12:00:00Z", "updatedAt": "2026-11-19T12:09:30Z" }
```

- IF `{deviceId}` does not exist in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found` (no cross-tenant existence disclosure — INV-EDGE-1).
- WHILE `lifecycleState != paired`, THE SYSTEM SHALL return `connectivity = null` (connectivity is meaningful only while paired — doc 03).
- THE SYSTEM SHALL return `detectionState`, `detectionStateSince`, `detectionReason`, `engineVersion` and `lastDetectingAt` reflecting the latest heartbeat, so a caregiver UI distinguishes a connected-but-not-detecting station from an offline one (ADR-005, INV-EDGE-9); `detectionState` is `UNKNOWN` when the station has reported none.
- Consumed by ACS's patient-session provisioner (G4) to confirm `paired` before `POST /acs/patient-sessions`.

### 2.4 `POST /edge/devices/{deviceId}/activation` — reactivate (authority `edge.device.activate`)

Reverses a `deactivate` (G3). Returns a `deactivated` device to `paired` and **re-issues a fresh
credential** (new `credentialId`); the previously-held credential stays dead. Response `200 OK`
with the §2.3 body; `connectivity` resets to `offline` until the next heartbeat.

EARS:

- WHILE a device is `deactivated`, WHEN a caller with `edge.device.activate` reactivates it, THE SYSTEM SHALL set `lifecycleState = paired`, mint a new `edge.device` credential (new `credentialId`), set `connectivity = offline`, respond `200 OK`, and audit `DeviceReactivated` to HIST.
- IF the device is already `paired`, THEN THE SYSTEM SHALL respond `200 OK` with no state change and no new credential (idempotent — SPEC-05).
- IF the device is `revoked`, THEN THE SYSTEM SHALL respond `409 Conflict` type `device-revoked` — a revoked device is never reactivated; it requires a new enroll + pair (INV-EDGE-6, doc 03).
- IF `{deviceId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 2.5 `POST /edge/devices/pair` — claim the pairing code (authority `edge.device.pair`, code-authenticated)

The **station** redeems its code and receives its device credential (ADR-003). This endpoint is
authenticated by the **single-use pairing code** presented in `X-Pairing-Code` — a bearer secret,
**not** a caregiver JWT — so it carries no `@PreAuthorize`; the `edge.device.pair` constant is
reserved in `RoleAuthorityPolicy` for op-name parity (D-639) and the enrolling coordinator holds
it. The same endpoint serves the fixed PC and the Android/Chromium mobile station (ADR-014) with
no separate path. Anchor action **DevicePaired**.

Request header: `X-Pairing-Code: WX7K-2Q9F`. Body:

```json
{ "stationFingerprint": "<opaque-ua-or-install-id>" }
```

Response `200 OK`:

```json
{ "deviceId": "<uuid>", "tenantId": "<uuid>", "patientId": "<uuid>",
  "deviceToken": "<jwt>", "tokenType": "Bearer", "actorType": "edge-device",
  "expiresIn": 900, "lifecycleState": "paired" }
```

EARS:

- WHEN a station presents an unexpired, unconsumed pairing code, THE SYSTEM SHALL resolve it in the **global** `device_pairing_code` table to `(tenantId, deviceId)`, consume it (set `consumedAt`), mint the `edge.device` token (§5), transition the device `awaiting_claim → paired`, set `pairedAt`, respond `200 OK`, and audit `DevicePaired` to HIST (INV-EDGE-3).
- IF the pairing code is missing, unknown, expired or already consumed, THEN THE SYSTEM SHALL respond `401 Unauthorized` type `invalid-pairing-code` and SHALL mint no credential (INV-EDGE-3, Risk R2).
- IF the referenced device is not in `awaiting_claim` (already paired / deactivated / revoked), THEN THE SYSTEM SHALL respond `409 Conflict` type `device-not-claimable`.
- THE SYSTEM SHALL mint the token with authorities restricted to `edge.heartbeat.record`, `edge.catalog.read` (+ the EVNT gesture-report right, G5) and SHALL NOT include any management, `acs.*`, `pat.*` or patient-session authority (INV-EDGE-2).

### 2.6 `DELETE /edge/devices/{deviceId}` — deactivate (authority `edge.device.deactivate`)

Reversible soft-disable (row retained; reversible via §2.4). Response `204 No Content`.

EARS:

- WHEN a caller with `edge.device.deactivate` deactivates a `paired` device of their tenant, THE SYSTEM SHALL set `lifecycleState = deactivated`, make its credential non-refreshable (heartbeat refresh denied), respond `204 No Content`, and audit `DeviceDeactivated` to HIST.
- IF the device is already `deactivated`, THEN THE SYSTEM SHALL respond `204 No Content` (idempotent — SPEC-05).
- IF `{deviceId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 2.7 `DELETE /edge/devices/{deviceId}/pairing` — unpair (authority `edge.device.unpair`)

Breaks the device↔patient binding and drops the cached catalog. Response `204 No Content`.

EARS:

- WHEN a caller with `edge.device.unpair` unpairs a device of their tenant, THE SYSTEM SHALL break the device↔patient binding, invalidate the current credential, drop the `cached_catalog`, respond `204 No Content`, and audit `DeviceUnpaired` to HIST.
- IF `{deviceId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 2.8 `DELETE /edge/devices/{deviceId}/credential` — revoke (authority `edge.device.revoke`)

**Terminal** credential kill (ADR-002, security action; CAREGIVER may call). Counterpart
**DeviceRevoked**. Response `204 No Content`.

EARS:

- WHEN a caller with `edge.device.revoke` revokes a device credential, THE SYSTEM SHALL set `lifecycleState = revoked`, add the `credentialId` to the revocation list in the same transaction, respond `204 No Content`, and audit `DeviceRevoked` to HIST (INV-EDGE-6).
- WHEN a credential is revoked, THE SYSTEM SHALL cause the next request bearing that device token to be rejected `401` (immediate invalidation via introspection / no further refresh — §6, G1).
- IF the target device is already `revoked`, THEN THE SYSTEM SHALL respond `204 No Content` (idempotent revoke — SPEC-05).
- THE SYSTEM SHALL NOT reinstate a `revoked` credential; returning to service requires a new enroll + pair (INV-EDGE-6).

## 3. Heartbeat (device endpoint — `edge.device` token)

### 3.1 `POST /edge/heartbeat` — record a liveness beat (authority `edge.heartbeat.record`)

The paired station records a periodic beat; absence beyond the watchdog threshold flips the device
`offline` (SPEC-02). The response may carry a **refreshed short-TTL token** (G1), coupling liveness
to credential freshness. Since **ADR-005 (SAFETY-GEST-1)** the beat also carries the station's
**detection state**, so EDGE distinguishes "connected but not detecting" from "offline".

Request (all detection fields optional — backwards compatible, §3.2):

```json
{ "sampledAt": "2026-11-19T12:09:30Z",
  "detectionState": "RUNNING",
  "detectionStateSince": "2026-11-19T12:05:00Z",
  "reason": null,
  "engineVersion": "1.4.2" }
```

`detectionState ∈ {RUNNING, PAUSED, DEGRADED, UNAVAILABLE}` (Java enum identifiers); optional
`reason` recommended values `HIDDEN | CAMERA_DENIED | MODEL_FAILED | LOW_FPS`. An omitted
`detectionState` is recorded as `UNKNOWN`, never `RUNNING` (INV-EDGE-9).

Response `200 OK`:

```json
{ "deviceId": "<uuid>", "connectivity": "online", "detectionState": "RUNNING",
  "serverTime": "2026-11-19T12:09:31Z", "refreshedToken": "<jwt-or-null>", "expiresIn": 900 }
```

EARS:

- WHEN a `paired` device presents a valid `edge.device` token holding `edge.heartbeat.record`, THE SYSTEM SHALL record `lastHeartbeatAt = now()`, set `connectivity = online`, persist the reported `detectionState` / `detectionStateSince` / `reason` / `engineVersion`, respond `200 OK`, and (WHERE the current token is within its refresh window) issue a `refreshedToken` (G1).
- WHEN a heartbeat reports `detectionState = RUNNING`, THE SYSTEM SHALL advance `lastDetectingAt = now()` and (WHERE an open detection-lapse episode exists) resolve it and audit `DetectionLapseResolved` (ADR-005, SPEC-02).
- WHERE a heartbeat omits `detectionState`, THE SYSTEM SHALL persist `UNKNOWN` and SHALL NOT advance `lastDetectingAt` (INV-EDGE-9, backwards compatible).
- WHEN a heartbeat arrives for a device whose `connectivity` was `offline`, THE SYSTEM SHALL flip it to `online` and audit `DeviceCameOnline` to HIST (SPEC-02).
- IF the device is not `paired` (`deactivated` / `revoked` / `awaiting_claim`), THEN THE SYSTEM SHALL respond `403 Forbidden` and SHALL NOT refresh the token (INV-EDGE-4, INV-EDGE-6).
- IF the presented `credentialId` is on the revocation list, THEN THE SYSTEM SHALL respond `401 Unauthorized` (INV-EDGE-6).

### 3.2 Backwards compatibility & detection-lapse surfacing (ADR-005)

- IF `detectionState` is present but not one of `RUNNING|PAUSED|DEGRADED|UNAVAILABLE`, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.
- THE SYSTEM SHALL treat an absent `detectionState` as `UNKNOWN` for all purposes, including the lapse sweep (silence/unknown ⇒ not `RUNNING`), so an older station is never assumed to be detecting (INV-EDGE-9).
- The detection **lapse** itself is not raised on the heartbeat path; a scheduled sweep raises it to EVNT after `N` minutes of non-`RUNNING`/silence (SPEC-02, `integration-contracts.md` §6.2). The heartbeat only records state and resolves an open lapse on the first `RUNNING` beat.

## 4. Catalog (device endpoint — `edge.device` token)

### 4.1 `GET /edge/catalog` — read the cached command catalog (authority `edge.catalog.read`)

Serves the last-good copy of the patient's PAT command catalog so detection survives offline
(ADR-004, INV-EDGE-5), behind EDGE's **own** ETag. EDGE refreshes from PAT opportunistically
(`integration-contracts.md` §1).

Response `200 OK` (+ `ETag: "<edge-etag>"`):

```json
{ "deviceId": "<uuid>", "patientId": "<uuid>", "fetchedAt": "2026-11-19T12:08:00Z",
  "stale": false,
  "commands": [ { "id": "<uuid>", "label": "suction", "urgency": "emergency",
    "sensitivity": "medium",
    "primaryPrimitive": { "id": "<uuid>", "code": "BLINK", "displayName": "Blink" },
    "secondaryPrimitive": null, "minGestureTimeMs": 300, "maxGestureTimeMs": 1200,
    "status": "active" } ] }
```

EARS:

- WHEN a `paired` device with `edge.catalog.read` reads its catalog, THE SYSTEM SHALL return the last `CachedCatalog` for that device's patient and respond `200 OK` with an EDGE `ETag` (§4.2).
- IF the device supplies `If-None-Match` equal to the current EDGE ETag, THEN THE SYSTEM SHALL respond `304 Not Modified` with no body (device skips re-download).
- IF PAT is unreachable when a refresh is attempted, THEN THE SYSTEM SHALL serve the last `CachedCatalog` and SHALL NOT hard-fail (INV-EDGE-5, ADR-004); THE SYSTEM SHALL set `stale = true` when the cache age exceeds EDGE's staleness hint.
- IF the device is not `paired`, THEN THE SYSTEM SHALL respond `403 Forbidden` (INV-EDGE-4).
- IF no catalog has ever been fetched for the patient (first pull not yet done and PAT unreachable), THEN THE SYSTEM SHALL respond `503 Service Unavailable` type `catalog-unavailable` (no cache to serve).

### 4.2 Conditional read / caching (ADR-004)

- THE SYSTEM SHALL compute a strong EDGE `ETag` from the cached payload signature (`pat_etag` + `fetchedAt`), distinct from PAT's upstream ETag (EDGE owns the device-facing ETag).
- WHEN a request supplies `If-None-Match` equal to the current EDGE `ETag`, THE SYSTEM SHALL respond `304 Not Modified`.
- THE SYSTEM SHALL expose `fetchedAt` so a client can observe staleness; EDGE, not PAT, owns how stale an offline edge may be (ADR-004 trade-off, Risk R3).

## 5. Device-token issuance & JWKS (device authorization endpoint)

EDGE mints the `edge.device` token on a successful pairing claim (§2.5) and on reactivation (§2.4)
and heartbeat refresh (§3.1). The token is a JWT signed by EDGE's signing key.

`edge.device` token claims:

| Claim | Value |
|---|---|
| `sub` | `deviceId` |
| `actorType` | `edge-device` |
| `deviceId`, `patientId`, `tenantId` | device binding |
| `authorities` | `["edge.heartbeat.record", "edge.catalog.read"]` (+ EVNT gesture-report right, G5) |
| `jti` / `kid` | `credentialId` — the key the revocation list and introspection check |
| `exp` | short TTL (default 900 s, G1), refreshed on heartbeat |

### 5.1 `GET /edge/.well-known/jwks.json` — EDGE device-token key set (public)

Returns the JSON Web Key Set resource servers (GWY/PAT/EVNT) use to verify EDGE-issued
`edge.device` signatures — so EDGE's signing key is trusted alongside ACS's (ADR-002).

- THE SYSTEM SHALL expose the active EDGE signing public key(s) as a JWKS document.

EARS — issuance:

- WHEN EDGE mints an `edge.device` token, THE SYSTEM SHALL restrict `authorities` to `edge.heartbeat.record` / `edge.catalog.read` (+ EVNT report right) and SHALL set a short `exp` (INV-EDGE-2, G1).
- THE SYSTEM SHALL sign the token with EDGE's key and SHALL publish the verification key via `/edge/.well-known/jwks.json` so GWY/PAT/EVNT validate it without ACS minting it.

## 6. Device-token introspection (immediate revocation — G1)

### 6.1 `POST /edge/device-tokens/introspect` — revocation-aware validation (service-client)

For a resource server (or GWY) to honor an immediate `edge.device` revoke without waiting for the
short TTL to lapse. Authority: internal **service-client** only.

Request: `{ "token": "<edge.device jwt>" }` → Response `200 OK`:
`{ "active": true, "sub": "<deviceId>", "actorType": "edge-device", "tenantId": "<uuid>", "patientId": "<uuid>", "authorities": [ ... ] }`.

EARS:

- WHEN the presented `edge.device` token is well-formed, unexpired and its `credentialId` is not on the revocation list, THE SYSTEM SHALL respond `active: true`.
- IF the token's `credentialId` is on the revocation list (device `revoked` / `unpaired`), THEN THE SYSTEM SHALL respond `active: false` (INV-EDGE-6).
- IF the caller is not a service-client, THEN THE SYSTEM SHALL respond `403 Forbidden`.

> **G1 resolution:** immediate revoke = short TTL refreshed on heartbeat (§3.1) **plus** this
> introspection consulted by resource servers on revoke-sensitive device calls. A revoked device's
> token is never refreshed (§3.1 returns `401`), so it dies within one TTL at worst and immediately
> on any introspected path.

## 8. Error model (RFC 7807)

All errors return `application/problem+json`:

```json
{ "type": "https://neuroassist/errors/<slug>", "title": "<short>", "status": 409,
  "detail": "<human message>", "instance": "/edge/devices/{id}", "correlationId": "<id>" }
```

| `type` slug | HTTP | Raised by |
|---|---|---|
| `unauthenticated` | 401 | missing/invalid/blacklisted human or device token |
| `invalid-pairing-code` | 401 | `POST /edge/devices/pair` — missing/unknown/expired/consumed code (INV-EDGE-3) |
| `forbidden` | 403 | authority check failed; device not `paired` on a device endpoint (INV-EDGE-4) |
| `not-found` | 404 | cross-tenant or missing device (no existence disclosure) |
| `validation-error` | 400 | malformed body / bad enum |
| `device-not-claimable` | 409 | `pair` on a device not in `awaiting_claim` |
| `device-revoked` | 409 | `activation` on a `revoked` device (INV-EDGE-6) |
| `catalog-unavailable` | 503 | `GET /edge/catalog` with no cache yet and PAT unreachable (INV-EDGE-5) |

EARS — error surface:

- THE SYSTEM SHALL return `application/problem+json` with a stable `type` URI, the HTTP `status`, and the request `correlationId` for every error response.
- IF an authority check fails, THEN THE SYSTEM SHALL respond `403 Forbidden` and SHALL NOT reveal whether the target device exists.

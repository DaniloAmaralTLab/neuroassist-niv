# EDGE — TechLab AI Hub Integration

> Service: `edge-service` · Module **EDGE — Edge Device Integration** · Project: NeuroAssist NIV

## Summary

**EDGE has no TechLab AI hub dependency.** The project does not integrate the TechLab AI hub:
`ai.hasAi = false`, and the `/new-project` phase `P3-techlab-ai-sync` is `skipped` (see
`project-context.json` → `setup.phases`). There is therefore no docs snapshot under
`integrations/techlab-ai/` and no Feign client to a hub bounded context.

| Hub bounded context | Used by EDGE? |
|---|---|
| orchestration | no |
| knowledge | no |
| document_composition | no |
| analytics | no |

EDGE is a device-lifecycle service: it monitors a local detection agent, it does not run AI (ADR-002
source — detection is on the edge; GEST owns detection truth). No hub call exists on any EDGE path.

## Propagation headers (for intra-project calls)

Although there is no hub, EDGE still propagates the standard correlation header on its outbound
synchronous calls (EDGE → PAT catalog pull; EDGE → ACS JWKS/service-client; EDGE → HIST audit — see
`integration-contracts.md`):

- `X-Correlation-Id` — echoed from the inbound request; generated by GWY if absent.
- Tenant and principal context travel inside the token (`tenantId`, `sub`, `actorType`), not as
  separate headers; `X-Tenant-Id` is never trusted (INV-EDGE-1).

If the hub is later adopted (institutional expansion), this file is where the Feign operations,
fallbacks and consumed hub events would be documented.

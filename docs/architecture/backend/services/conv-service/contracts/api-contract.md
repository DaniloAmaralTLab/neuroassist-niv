# CONV — API Contract

> Service: `conv-service` · Module **CONV — Conversation via Speech Tree** · Project: NeuroAssist NIV
> Stack: Java 21 / Spring Boot (hexagonal — `../../../adr/ADR-001-hexagonal-architecture.md`,
> key `hexagonal_java`) · Multi-tenant (schema-per-tenant) · Messaging disabled.
> EARS authoring guide: `../../../standards/ears-notation.md`.

CONV is an **ACS resource server** on its station (patient-session) endpoints — it validates the
ACS-minted patient-session token via ACS JWKS and mints no token of its own. Its publish/erasure
endpoints are **TRN service-client** only. Tenant context on every authenticated endpoint derives
from the JWT `tenantId` claim (INV-CONV-7); `X-Tenant-Id` is never trusted. The patient's live
navigation and playback run **client-side over the cached bundle** — CONV is not called per phrase
(ADR-003/ADR-004, INV-CONV-5).

---

## 0. Conventions

- **Base path:** `/conv`. GWY (API Gateway) fronts the service; paths below are as seen by the controller.
- **Media type:** `application/json`; audio responses are the clip's own media type (e.g. `audio/mpeg`). Errors use `application/problem+json` (RFC 7807).
- **Identifiers:** all resource ids are UUID (string, canonical form); `assetId` is a stable string id from the published manifest.
- **Authority model:** fine-grained authorities follow `conv.<resource>.<action>`, sourced from the single `RoleAuthorityPolicy` (SPEC-06). Controller `@PreAuthorize` strings MUST equal those constants (D-535, D-639).
- **State-changing verbs** map to `POST` / `DELETE` only; `GET` is side-effect free.
- **No public endpoints** other than `GET /conv/health` (SPEC-07). The patient-session token is required on every station endpoint; publish/erasure require a TRN service-client token.

### 0.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `Authorization: Bearer <jwt>` | request | Required on every endpoint except `GET /conv/health` (public). Station endpoints require the ACS patient-session token; `/conv/trees`, `/conv/tree-versions/*`, `DELETE /conv/patients/{id}/audio` require the TRN service-client token. |
| `X-Correlation-Id` | request/response | Propagated end-to-end; generated by GWY if absent, echoed on the response and on every HIST audit call. |
| `X-Tenant-Id` | — | **Never trusted from the request.** Tenant context is derived from the JWT `tenantId` claim only (INV-CONV-7). |
| `If-None-Match` | request | Optional on `GET /conv/tree`; enables conditional `304` (§2.2, ADR-003). |
| `ETag` | response | Strong ETag returned on `GET /conv/tree` and on `GET /conv/audio/{assetId}` for station-side caching. |
| `Cache-Control` | response | `GET /conv/audio/{assetId}` returns `Cache-Control: public, max-age=31536000, immutable` (audio URLs are immutable — §3). |

EARS — headers & auth:

- WHEN a protected CONV endpoint receives a request without a valid `Authorization` bearer token, THE SYSTEM SHALL respond `401 Unauthorized`.
- IF a request supplies an `X-Tenant-Id` header, THEN THE SYSTEM SHALL ignore it and derive tenant context exclusively from the JWT `tenantId` claim (INV-CONV-7).
- THE SYSTEM SHALL echo the received `X-Correlation-Id` on every response and on every downstream HIST audit call.

### 0.2 Token types consumed

| Token | Issuer | `actorType` | Used on | Validated via |
|---|---|---|---|---|
| patient-session | ACS | `patient-session` | §2 tree read, §3 audio read, §4 usage | ACS JWKS; authorities restricted to `conv.*`/`gest.*` (ACS INV-3) |
| service-client (TRN) | ACS | `service-client` | §5 publish, §6 retire, §7 erase | ACS JWKS |

> The patient-session token is **rejected `403`** on every publish/retire/erase path (those are
> TRN-only). The TRN service-client token is rejected `403` on the station read/usage paths.

## 2. Tree bundle (station — patient-session)

### 2.1 `GET /conv/tree` — read the published per-patient bundle (authority `conv.tree.read`)

Returns the **active** immutable `TreeVersion` for the patient bound to the session (categories →
phrases + the audio manifest), behind a **strong ETag** derived from the version `contentHash`
(INV-CONV-4). The station persists this bundle and runs it offline; it refreshes opportunistically
with `If-None-Match` (ADR-003). The `patientId` is taken from the patient-session token, not the URL.

Response `200 OK` (+ `ETag: "<contentHash>"`):

```json
{
  "patientId": "<uuid>",
  "version": 7,
  "etag": "\"sha256:4f1c...\"",
  "contentHash": "sha256:4f1c...",
  "publishedAt": "2026-11-20T12:00:00Z",
  "tree": {
    "categories": [
      { "id": "cat-needs", "label": "Needs", "order": 1,
        "children": ["cat-needs-comfort"],
        "phrases": [
          { "id": "phr-suction", "text": "I need suction, please.", "order": 1, "assetId": "aud-suction-01" }
        ] }
    ]
  },
  "audioManifest": [
    { "assetId": "aud-suction-01",
      "url": "/conv/audio/aud-suction-01",
      "contentHash": "sha256:9ab3...",
      "mediaType": "audio/mpeg",
      "durationMs": 1400 }
  ]
}
```

EARS:

- WHEN a station presenting a valid patient-session token with `conv.tree.read` requests the tree, THE SYSTEM SHALL return the single `active` `TreeVersion` of that patient and respond `200 OK` with a strong `ETag` equal to the version `contentHash` (INV-CONV-2, INV-CONV-4).
- WHEN the request supplies `If-None-Match` equal to the current `ETag`, THE SYSTEM SHALL respond `304 Not Modified` with no body (the station keeps its cached bundle — ADR-003).
- THE SYSTEM SHALL include, for every phrase in the active version, an `audioManifest` entry whose `assetId` resolves within the same version (INV-CONV-3 — no dangling audio).
- THE SYSTEM SHALL derive `patientId` and tenant from the patient-session token claims and SHALL ignore any patient/tenant supplied in the request (INV-CONV-7).
- IF the patient bound to the session has no `active` version yet (never provisioned), THEN THE SYSTEM SHALL respond `404 Not Found` type `tree-not-published` (cold station — see SPEC-10 §4 provisioning INT item).
- THE SYSTEM SHALL serve only data of the caller's tenant; cross-tenant bundles are never disclosed (INV-CONV-7).

### 2.2 Conditional read / caching (ADR-003)

- THE SYSTEM SHALL compute a **strong** `ETag` as a pure function of the version `contentHash`; equal `ETag` ⇒ byte-identical bundle (INV-CONV-4, enables safe `304`).
- WHEN a published change makes a newer version `active`, THE SYSTEM SHALL serve the new `ETag` on the next read; the station holding the previous bundle keeps working until it successfully refreshes (stale-but-usable — ADR-003, INV-CONV-5).

## 3. Audio (station — patient-session)

### 3.1 `GET /conv/audio/{assetId}` — stream a cached audio clip (authority `conv.audio.read`)

Serves/streams the **pre-synthesized** clip for `{assetId}` from blob storage via `AudioAssetPort`.
CONV never synthesizes and never calls ElevenLabs (ADR-005). URLs are **immutable** — a given
`assetId` always maps to byte-identical audio with a stable `contentHash`; a new recording is a new
`assetId` in a new version. Supports HTTP range requests for progressive playback.

Response `200 OK` (or `206 Partial Content` for a range) with the clip bytes, `Content-Type` of the
clip, `ETag: "<contentHash>"`, `Cache-Control: public, max-age=31536000, immutable`.

EARS:

- WHEN a station with `conv.audio.read` requests an `assetId` present in the patient's active version manifest, THE SYSTEM SHALL stream the cached clip `200 OK` with the clip media type, a strong `ETag` equal to the clip `contentHash`, and an immutable `Cache-Control` (ADR-003).
- WHERE the request carries a `Range` header, THE SYSTEM SHALL respond `206 Partial Content` with the requested byte range.
- IF `{assetId}` is not referenced by the caller's patient in any readable version, THEN THE SYSTEM SHALL respond `404 Not Found` (no cross-tenant/cross-patient disclosure — INV-CONV-7).
- IF the clip has been crypto-shredded (erasure — §7, ADR-005/ADR-006), THEN THE SYSTEM SHALL respond `410 Gone` type `audio-erased`.
- THE SYSTEM SHALL NOT call any TTS vendor on this path and SHALL serve only bytes already cached (ADR-005, INV-CONV-5).

## 4. Usage signal (station — patient-session, opt-in)

### 4.1 `POST /conv/usage-signals` — record an opt-in minimal usage signal (authority `conv.usage.record`)

Records that a phrase was spoken: `phraseId` + client timestamp only, **no free text** (INV-CONV-6).
Opt-in: written only when usage logging is consented for the patient. **Never blocks playback** — the
station queues signals and flushes opportunistically; the response is advisory. Idempotent on
`idempotencyKey`.

Request:

```json
{ "phraseId": "phr-suction", "occurredAt": "2026-11-20T12:05:00Z",
  "idempotencyKey": "<patientId>:phr-suction:2026-11-20T12:05:00Z" }
```

Response `202 Accepted` (`{ "status": "RECORDED", "replay": false }`) — or `200 OK` on idempotent replay.

EARS:

- WHILE usage logging is opted in for the patient, WHEN a station with `conv.usage.record` posts a usage signal, THE SYSTEM SHALL persist `{tenantId, patientId, phraseId, occurredAt}` and respond `202 Accepted` (INV-CONV-6).
- WHEN a signal arrives whose `idempotencyKey` was already stored, THE SYSTEM SHALL respond `200 OK` and SHALL NOT write a duplicate (SPEC-05).
- WHILE usage logging is **not** opted in for the patient, WHEN a usage signal is posted, THE SYSTEM SHALL respond `202 Accepted` and SHALL discard it without persisting (opt-in; never an error — playback is never affected, INV-CONV-5).
- IF the body contains any field other than `phraseId`, `occurredAt`, `idempotencyKey` (e.g. free text), THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error` (INV-CONV-6).
- THE SYSTEM SHALL NOT audit this to HIST — a usage signal is never a compliance fact (ADR-006, INV-CONV-6).

## 5. Publish (TRN service-client)

### 5.1 `POST /conv/trees` — publish a new immutable tree version (authority `conv.tree.publish`)

TRN **pushes** an approved, immutable tree version to CONV (authoring → runtime, ADR-005). CONV
creates a new `TreeVersion`, makes it `active`, **supersedes** the previously active version
(side-effect of the same transaction — no separate authority), computes its `contentHash`/`ETag`,
and audits `TreePublished` (+ `TreeVersionSuperseded`) to HIST **hard-502** (ADR-006).

Request:

```json
{
  "patientId": "<uuid>",
  "sourceVersionRef": "trn:approval:<uuid>",
  "tree": { "categories": [ /* categories → phrases, each phrase.assetId */ ] },
  "audioManifest": [
    { "assetId": "aud-suction-01", "storageRef": "blob://conv/.../aud-suction-01.mp3",
      "voiceModelRef": "vm:<subjectKeyId>", "mediaType": "audio/mpeg",
      "durationMs": 1400, "contentHash": "sha256:9ab3..." }
  ],
  "idempotencyKey": "trn:publish:<approvalId>"
}
```

Response `201 Created` (+ `Location: /conv/tree-versions/{versionId}`):

```json
{ "versionId": "<uuid>", "patientId": "<uuid>", "version": 7,
  "etag": "\"sha256:4f1c...\"", "contentHash": "sha256:4f1c...",
  "status": "active", "supersededVersionId": "<uuid-or-null>",
  "publishedAt": "2026-11-20T12:00:00Z" }
```

EARS:

- WHEN a TRN service-client with `conv.tree.publish` posts an approved tree version for a patient, THE SYSTEM SHALL create a new immutable `TreeVersion`, set it `active`, set the previously active version `superseded`, compute its `contentHash` and strong `ETag`, respond `201 Created`, and audit `TreePublished` and `TreeVersionSuperseded` to HIST in the same transaction (hard-502 — ADR-006, INV-CONV-1, INV-CONV-2).
- IF any phrase in the submitted tree references an `assetId` absent from `audioManifest`, THEN THE SYSTEM SHALL reject the publish `422 Unprocessable Entity` type `dangling-audio-reference` and persist nothing (INV-CONV-3).
- IF the HIST audit of `TreePublished` fails, THEN THE SYSTEM SHALL roll back the publish and respond `502 Bad Gateway` type `audit-unavailable` (hard-502 — ADR-006).
- WHEN a publish arrives whose `idempotencyKey` was already applied, THE SYSTEM SHALL respond `200 OK` with the existing version and SHALL NOT create a duplicate (SPEC-05).
- IF the caller presents a patient-session token instead of a TRN service-client token, THEN THE SYSTEM SHALL respond `403 Forbidden` (publish is TRN-only; ACS INV-3).
- THE SYSTEM SHALL NOT mutate any existing `TreeVersion` in place — a change is always a new version (INV-CONV-1).

## 6. Retire a version (TRN service-client — withdraw)

### 6.1 `POST /conv/tree-versions/{versionId}:retire` — withdraw a version (authority `conv.tree-version.retire`)

Withdraws a tree version (`active` or `superseded`) → `withdrawn` (terminal). Audited to HIST with
the **commit + durable-retry** class (erasure/right-to-be-forgotten must never be blocked by a HIST
outage — ADR-006). If the withdrawn version was `active`, the patient has **no active version** until
the next publish (the station keeps its last good cached bundle — ADR-003).

Response `200 OK` (`{ "versionId": "<uuid>", "status": "withdrawn", "withdrawnAt": "..." }`).

EARS:

- WHEN a TRN service-client with `conv.tree-version.retire` retires a version, THE SYSTEM SHALL set its `status = withdrawn`, respond `200 OK`, and audit `TreeVersionWithdrawn` to HIST (commit + durable-retry — ADR-006).
- IF the version is already `withdrawn`, THEN THE SYSTEM SHALL respond `200 OK` with no state change (idempotent — SPEC-05).
- IF `{versionId}` does not exist in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found` (no cross-tenant disclosure — INV-CONV-7).
- WHEN HIST is unreachable at retire time, THE SYSTEM SHALL commit the `withdrawn` transition, enqueue the audit on a durable queue, respond `200 OK`, and retry the `TreeVersionWithdrawn` fact idempotently until accepted (ADR-006 — erasure never blocks).
- IF the caller is not a TRN service-client, THEN THE SYSTEM SHALL respond `403 Forbidden`.

## 7. Erase audio (TRN service-client — crypto-shred)

### 7.1 `DELETE /conv/patients/{patientId}/audio` — erase a patient's audio assets (authority `conv.audio.delete`)

Right-to-be-forgotten erasure of the patient's cloned-voice audio (ADR-005/ADR-006): CONV
**crypto-shreds** the per-subject key so cached audio and the `voiceModelRef` become unreadable, marks
the affected versions `withdrawn`, retains the immutable records with the payload rendered
unreadable, and audits `AudioAssetsErased` with the **commit + durable-retry** class. CONV stores no
voice samples or voice model (those are TRN) — it erases only its own references/clips.

Response `202 Accepted` (`{ "patientId": "<uuid>", "status": "ERASED", "erasedAssetCount": 42, "withdrawnVersionCount": 7 }`).

EARS:

- WHEN a TRN service-client with `conv.audio.delete` requests erasure for a patient, THE SYSTEM SHALL delete the per-subject key (crypto-shred), render the cached audio and `voiceModelRef` unreadable, set affected versions `withdrawn`, respond `202 Accepted`, and audit `AudioAssetsErased` to HIST (commit + durable-retry — ADR-005/ADR-006).
- WHEN HIST is unreachable at erasure time, THE SYSTEM SHALL complete the crypto-shred, enqueue the `AudioAssetsErased` fact on a durable queue, respond `202 Accepted`, and retry idempotently until accepted (erasure never blocks — ADR-006).
- WHEN audio for the patient has already been erased, THE SYSTEM SHALL respond `202 Accepted` with `erasedAssetCount: 0` (idempotent — SPEC-05).
- WHEN audio has been erased, THE SYSTEM SHALL cause `GET /conv/audio/{assetId}` for those clips to respond `410 Gone` (§3.1).
- IF the caller is not a TRN service-client, THEN THE SYSTEM SHALL respond `403 Forbidden`.

## 8. Operational

### 8.1 `GET /conv/health` — liveness/readiness (public, SPEC-07)

Spring Boot Actuator health. `200 OK` `{ "status": "UP" }` / `503` when a hard dependency (datastore,
blob storage) is down. ACS/PAT/HIST reachability is a **readiness detail**, never a hard failure of
the station read path (the station serves from cache — INV-CONV-5).

## 9. Error model (RFC 7807)

All errors return `application/problem+json`:

```json
{ "type": "https://neuroassist/errors/<slug>", "title": "<short>", "status": 409,
  "detail": "<human message>", "instance": "/conv/tree", "correlationId": "<id>" }
```

| `type` slug | HTTP | Raised by |
|---|---|---|
| `unauthenticated` | 401 | missing/invalid/blacklisted token |
| `forbidden` | 403 | authority check failed; wrong token class (patient-session on a TRN path or vice-versa, ACS INV-3) |
| `tree-not-published` | 404 | `GET /conv/tree` — patient has no active version (cold/first-sync, SPEC-10 §4) |
| `not-found` | 404 | cross-tenant/cross-patient or missing asset/version (no existence disclosure) |
| `validation-error` | 400 | malformed body / usage signal carrying forbidden fields (INV-CONV-6) |
| `dangling-audio-reference` | 422 | publish whose phrase references an `assetId` absent from the manifest (INV-CONV-3) |
| `audit-unavailable` | 502 | publish rolled back because the `TreePublished` HIST audit failed (hard-502, ADR-006) |
| `audio-erased` | 410 | `GET /conv/audio/{assetId}` for a crypto-shredded clip (ADR-005) |

EARS — error surface:

- THE SYSTEM SHALL return `application/problem+json` with a stable `type` URI, the HTTP `status`, and the request `correlationId` for every error response.
- IF an authority or token-class check fails, THEN THE SYSTEM SHALL respond `403 Forbidden` and SHALL NOT reveal whether the target resource exists.

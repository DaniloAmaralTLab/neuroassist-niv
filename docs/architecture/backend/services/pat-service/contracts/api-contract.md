# PAT — API Contract

> Service: `pat-service` · Module **PAT — Patients and Command Catalog** · Project: NeuroAssist NIV
> Stack: Java 21 / Spring Boot (hexagonal — `../../../adr/ADR-001-hexagonal-architecture.md`,
> key `hexagonal_java`) · Multi-tenant (schema-per-tenant) · Messaging disabled.
> EARS authoring guide: `../../../standards/ears-notation.md`.

PAT is an **ACS resource server**: it validates ACS-issued JWTs (JWKS) and never issues
tokens. It owns the `Patient` and `Command` aggregates (per-tenant) and the global
`GestureType` primitive catalog, and exposes the catalog-read surface the detection and
notification modules (EDGE, GEST, EVNT, DASH, CONV) consume. Tenant context is derived
exclusively from the JWT `tenantId` claim (INV-PAT-1); `X-Tenant-Id` is never trusted.

---

## 0. Conventions

- **Base path:** `/pat`. GWY (API Gateway) fronts the service; paths below are as seen by
  the controller.
- **Media type:** `application/json`. Errors use `application/problem+json` (RFC 7807).
- **Identifiers:** all resource ids are UUID (string, canonical form).
- **Authority model:** fine-grained authorities follow `pat.<resource>.<action>`, sourced
  from the single `RoleAuthorityPolicy` (SPEC-06). Controller `@PreAuthorize` strings MUST
  equal those constants (INV-PAT-8, D-535).
- **State-changing verbs** map to `POST` / `PATCH` / `DELETE` only (domain-framing
  convention). `GET` is side-effect free.

### 0.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `Authorization: Bearer <jwt>` | request | Required on **every** PAT endpoint (PAT has no public endpoint; it issues no token). |
| `X-Correlation-Id` | request/response | Propagated end-to-end; generated by GWY if absent, echoed on the response and on every HIST audit call. |
| `X-Tenant-Id` | — | **Never trusted from the request.** Tenant context is derived from the JWT `tenantId` claim only (INV-PAT-1). |
| `If-None-Match` | request | Optional on catalog reads; enables conditional `304` (§3.2). |
| `ETag` | response | Returned on catalog reads for edge/detection caching (ADR-004, §3.2). |

EARS — headers & auth:

- WHEN a PAT endpoint receives a request without a valid `Authorization` bearer token, THE SYSTEM SHALL respond `401 Unauthorized`.
- IF a request supplies an `X-Tenant-Id` header, THEN THE SYSTEM SHALL ignore it and derive tenant context exclusively from the JWT `tenantId` claim (INV-PAT-1).
- WHEN a request bears a bearer token whose `jti` is blacklisted (verified via ACS introspection on sensitive reads), THE SYSTEM SHALL respond `401 Unauthorized`.
- THE SYSTEM SHALL echo the received `X-Correlation-Id` on every response and on every downstream HIST audit call.
- IF a request carries a `patient-session` token (authorities `conv.*` / `gest.*` only, ACS INV-3), THEN THE SYSTEM SHALL respond `403 Forbidden` on every `/pat` endpoint (INV-PAT-7).

### 0.2 JWT claims consumed (issued by ACS)

| Claim | Used by PAT for |
|---|---|
| `sub` | caregiver id (`createdBy`) or service-client id — audit `actorId` |
| `tenantId` | tenant routing + `tenant_id` column (INV-PAT-1) |
| `actorType` | `caregiver` \| `patient-session` \| service-client — gate selection |
| `authorities` | `pat.*` authority checks (SPEC-06); `conv.*`/`gest.*`-only tokens are rejected |
| `jti` | revocation check via ACS `/acs/auth/introspect` on sensitive reads |

## 1. Patients

### 1.1 `POST /pat/patients` — register a patient (authority `pat.patient.create`)

Request:

```json
{ "label": "Dona Maria", "deviceId": "<uuid-or-null>" }
```

Response `201 Created` (+ `Location: /pat/patients/{id}`):

```json
{ "id": "<uuid>", "tenantId": "<uuid>", "label": "Dona Maria",
  "deviceId": "<uuid-or-null>", "status": "active", "createdBy": "<caregiverId>",
  "createdAt": "2026-11-19T12:00:00Z" }
```

EARS:

- WHEN a caller with `pat.patient.create` registers a patient, THE SYSTEM SHALL create it in the caller's tenant with `status = active` and respond `201 Created`.
- THE SYSTEM SHALL set `tenantId` from the JWT claim and `createdBy` from the JWT `sub`, and SHALL ignore any tenant supplied in the body (INV-PAT-1).
- WHERE `deviceId` is present, THE SYSTEM SHALL store it as an opaque reference to EDGE without a cross-service FK (A5); WHERE it is absent, THE SYSTEM SHALL allow the patient to exist unpaired.
- WHEN registration succeeds, THE SYSTEM SHALL audit `PatientRegistered` to HIST within the same request.

### 1.2 `GET /pat/patients` — list patients in tenant (authority `pat.patient.read`)

Query: `?status=active|inactive|all` (default `active`). Response `200 OK`:

```json
{ "patients": [ { "id": "<uuid>", "label": "Dona Maria", "deviceId": "<uuid-or-null>", "status": "active" } ] }
```

- THE SYSTEM SHALL return only patients of the caller's tenant (INV-PAT-1); cross-tenant rows are never disclosed.

### 1.3 `GET /pat/patients/{patientId}` — read one patient (authority `pat.patient.read`)

Response `200 OK`: `{ "id", "tenantId", "label", "deviceId", "status", "createdBy", "createdAt", "updatedAt" }`.

- IF `{patientId}` does not exist in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found` (no cross-tenant existence disclosure — INV-PAT-2).

### 1.4 `DELETE /pat/patients/{patientId}` — deactivate (authority `pat.patient.deactivate`)

Soft deactivation (row retained). Response `204 No Content`.

EARS:

- WHEN a caller with `pat.patient.deactivate` deactivates a patient of their tenant, THE SYSTEM SHALL set `status = inactive`, retain the row, and respond `204 No Content`.
- IF the target patient belongs to a different tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.
- WHEN deactivation succeeds, THE SYSTEM SHALL audit `PatientDeactivated` to HIST within the same request.

### 1.5 `POST /pat/patients/{patientId}/activation` — reactivate (authority `pat.patient.activate`)

Returns an `inactive` patient to `active` (state machine, doc 03). Response `200 OK` with the patient body.

EARS:

- WHILE a patient is `inactive`, WHEN a caller with `pat.patient.activate` reactivates it, THE SYSTEM SHALL set `status = active`, respond `200 OK`, and audit `PatientReactivated` to HIST.
- IF the patient is already `active`, THEN THE SYSTEM SHALL respond `200 OK` with no state change (idempotent — SPEC-05).

## 2. Commands (per-patient catalog)

### 2.1 `POST /pat/patients/{patientId}/commands` — create a command (authority `pat.command.create`)

Request:

```json
{ "label": "suction", "urgency": "emergency", "sensitivity": "medium",
  "primaryPrimitive": "<gestureTypeId>", "secondaryPrimitive": "<gestureTypeId-or-null>",
  "minGestureTimeMs": 300, "maxGestureTimeMs": 1200 }
```

Response `201 Created` (+ `Location: /pat/commands/{id}`): the full command body (§2.4 shape).

EARS:

- WHEN a caller with `pat.command.create` adds a command to a patient of their tenant, THE SYSTEM SHALL create it with `status = active` and respond `201 Created`.
- IF `{patientId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found` (INV-PAT-2).
- IF `minGestureTimeMs <= 0` or `maxGestureTimeMs < minGestureTimeMs`, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error` (INV-PAT-3).
- IF `primaryPrimitive` is absent or references no existing `GestureType`, THEN THE SYSTEM SHALL respond `400 Bad Request` type `unknown-gesture-type` (INV-PAT-4, application-layer check — SPEC-04 G2).
- IF `secondaryPrimitive` equals `primaryPrimitive`, or references no existing `GestureType`, THEN THE SYSTEM SHALL respond `400 Bad Request` (INV-PAT-4).
- IF `urgency` is not in `emergency|routine` or `sensitivity` is not in `low|medium|high`, THEN THE SYSTEM SHALL respond `400 Bad Request`.
- WHEN creation succeeds, THE SYSTEM SHALL audit `CommandCalibrated` (anchor) to HIST within the same request.

### 2.2 `GET /pat/patients/{patientId}/commands` — read the patient's catalog (authority `pat.command.read`)

The **catalog-pull endpoint** (ADR-004). Query: `?status=active|retired|all` (default `active`).
Returns an `ETag` for conditional refresh (§3.2).

Response `200 OK`:

```json
{ "patientId": "<uuid>", "commands": [
  { "id": "<uuid>", "label": "suction", "urgency": "emergency", "sensitivity": "medium",
    "primaryPrimitive": { "id": "<uuid>", "code": "BLINK", "displayName": "Blink" },
    "secondaryPrimitive": null, "minGestureTimeMs": 300, "maxGestureTimeMs": 1200,
    "status": "active" } ] }
```

EARS:

- WHEN a caller with `pat.command.read` (caregiver token or detection service client) reads a patient's catalog, THE SYSTEM SHALL return the commands of that patient filtered by `status` and respond `200 OK` with an `ETag`.
- WHILE `status = active` (the default), THE SYSTEM SHALL exclude every `retired` command (INV-PAT-5).
- THE SYSTEM SHALL resolve `primaryPrimitive` / `secondaryPrimitive` to `{ id, code, displayName }` so the detection agent needs no second call (ADR-004).
- IF `{patientId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 2.3 `GET /pat/commands/{commandId}` — read one command (authority `pat.command.read`)

Single-command read (EVNT uses this for `urgency` + `label` by id). Response `200 OK`: the §2.4 body.

- IF `{commandId}` is not in the caller's tenant, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 2.4 `PATCH /pat/commands/{commandId}` — calibrate / re-map (authority `pat.command.calibrate`)

Partial update of calibration and mapping: `label`, `urgency`, `sensitivity`,
`primaryPrimitive`, `secondaryPrimitive`, `minGestureTimeMs`, `maxGestureTimeMs`.

Response `200 OK`:

```json
{ "id": "<uuid>", "patientId": "<uuid>", "tenantId": "<uuid>", "label": "suction",
  "urgency": "emergency", "sensitivity": "high",
  "primaryPrimitive": { "id": "<uuid>", "code": "BLINK", "displayName": "Blink" },
  "secondaryPrimitive": null, "minGestureTimeMs": 300, "maxGestureTimeMs": 1500,
  "status": "active", "createdBy": "<caregiverId>",
  "createdAt": "2026-11-19T12:00:00Z", "updatedAt": "2026-11-19T13:00:00Z" }
```

EARS:

- WHEN a caller with `pat.command.calibrate` updates an `active` command of their tenant, THE SYSTEM SHALL apply the changed fields, bump `updatedAt`, respond `200 OK`, and audit `CommandCalibrated` (anchor) to HIST.
- THE SYSTEM SHALL re-validate the calibration window and gesture composition on every update (INV-PAT-3, INV-PAT-4) and SHALL reject an invalid change with `400 Bad Request` without mutating the row.
- IF the command is `retired`, THEN THE SYSTEM SHALL respond `409 Conflict` type `command-retired` (INV-PAT-5 — a retired command is never silently re-tuned; create a new one).

### 2.5 `DELETE /pat/commands/{commandId}` — retire (authority `pat.command.retire`)

Soft-retire (terminal; row retained). Response `204 No Content`.

EARS:

- WHEN a caller with `pat.command.retire` retires an `active` command of their tenant, THE SYSTEM SHALL set `status = retired`, retain the row, respond `204 No Content`, and audit `CommandRetired` to HIST.
- WHEN a command is retired, THE SYSTEM SHALL exclude it from the default (`active`) catalog read while keeping it resolvable by id for historical EVNT/HIST references (INV-PAT-5).
- IF the command is already `retired`, THEN THE SYSTEM SHALL respond `204 No Content` (idempotent retire — SPEC-05).

## 3. Gesture-type catalog (global primitives)

### 3.1 `GET /pat/gesture-types` — list the primitive vocabulary (authority `pat.gesture-type.read`)

The shared global vocabulary a command composes from. Readable by any authenticated actor
holding `pat.gesture-type.read` and by detection service clients. Returns an `ETag`.

Response `200 OK`:

```json
{ "gestureTypes": [ { "id": "<uuid>", "code": "BLINK", "displayName": "Blink",
  "description": "A single deliberate eyelid closure." } ] }
```

- THE SYSTEM SHALL return the global `gesture_type` catalog regardless of tenant (it is the shared vocabulary — ADR-002).
- THE SYSTEM SHALL NOT assert detection-engine support for any listed primitive; a `GestureType` is a name in the vocabulary only (INV-PAT-6, GEST owns support truth).

### 3.2 `GET /pat/gesture-types/{id}` — read one primitive (authority `pat.gesture-type.read`)

Response `200 OK`: `{ "id", "code", "displayName", "description", "createdAt" }`.
`404 Not Found` if absent.

### 3.3 `POST /pat/gesture-types` — register a primitive (authority `pat.gesture-type.create`)

Append-only (MVP). Request: `{ "code": "DOUBLE_BLINK", "displayName": "Double blink", "description": "..." }`.
Response `201 Created`: the created primitive.

EARS:

- WHEN a caller with `pat.gesture-type.create` adds a primitive, THE SYSTEM SHALL create a global `gesture_type` row and respond `201 Created`, and audit `GestureTypeRegistered` to HIST.
- IF `code` already exists, THEN THE SYSTEM SHALL respond `409 Conflict` type `gesture-type-code-taken` (globally unique).
- THE SYSTEM SHALL NOT delete a primitive in the MVP (removing one would orphan commands — append-only, doc 05 data lifecycle).

### 3.3.1 Conditional read / caching (ADR-004, edge distribution)

Applies to `GET /pat/patients/{patientId}/commands` (§2.2) and `GET /pat/gesture-types` (§3.1).

- THE SYSTEM SHALL compute a strong `ETag` for a catalog response from the resource's version signature (`max(updated_at)` + row count for a patient's commands; `max(created_at)` + count for gesture-types).
- WHEN a request supplies `If-None-Match` equal to the current `ETag`, THE SYSTEM SHALL respond `304 Not Modified` with no body (edge/detection skips re-download — ADR-004).
- THE SYSTEM SHALL set `Cache-Control: private, max-age=30` on catalog responses as a refresh hint; the authoritative staleness tolerance of an **offline** edge is owned by EDGE, which runs the last-fetched catalog until it can refresh (ADR-004 trade-off).

## 4. Error model (RFC 7807)

All errors return `application/problem+json`:

```json
{ "type": "https://neuroassist/errors/<slug>", "title": "<short>", "status": 400,
  "detail": "<human message>", "instance": "/pat/patients/{id}/commands", "correlationId": "<id>" }
```

| `type` slug | HTTP | Raised by |
|---|---|---|
| `unauthenticated` | 401 | any endpoint — missing/invalid/blacklisted token |
| `forbidden` | 403 | authority check failed; patient-session token on any `/pat` endpoint (INV-PAT-7) |
| `not-found` | 404 | cross-tenant or missing resource (no existence disclosure) |
| `validation-error` | 400 | malformed body / bad enum / bad calibration window (INV-PAT-3) |
| `unknown-gesture-type` | 400 | `primaryPrimitive`/`secondaryPrimitive` not in the catalog (INV-PAT-4) |
| `command-retired` | 409 | `PATCH` on a retired command (INV-PAT-5) |
| `gesture-type-code-taken` | 409 | duplicate `code` on `POST /pat/gesture-types` |

EARS — error surface:

- THE SYSTEM SHALL return `application/problem+json` with a stable `type` URI, the HTTP `status`, and the request `correlationId` for every error response.
- IF an authority check fails, THEN THE SYSTEM SHALL respond `403 Forbidden` and SHALL NOT reveal whether the target resource exists.

|---|---|---|---|
| `/pat/patients` | POST | `pat.patient.create` | CAREGIVER, CLINIC_COORDINATOR |
| `/pat/patients` | GET | `pat.patient.read` | CAREGIVER, CLINIC_COORDINATOR (incl. via the caregiver dashboard — DASH has no backend, DASH ADR-001), service client (CONV) |
| `/pat/patients/{id}` | GET | `pat.patient.read` | CAREGIVER, CLINIC_COORDINATOR, service client |
| `/pat/patients/{id}` | DELETE | `pat.patient.deactivate` | CLINIC_COORDINATOR |
| `/pat/patients/{id}/activation` | POST | `pat.patient.activate` | CLINIC_COORDINATOR |
| `/pat/patients/{id}/commands` | POST | `pat.command.create` | CAREGIVER, CLINIC_COORDINATOR |
| `/pat/patients/{id}/commands` | GET | `pat.command.read` | CAREGIVER, CLINIC_COORDINATOR, detection service client (GEST/EDGE) |
| `/pat/commands/{id}` | GET | `pat.command.read` | CAREGIVER, CLINIC_COORDINATOR, service client (EVNT) |
| `/pat/commands/{id}` | PATCH | `pat.command.calibrate` | CAREGIVER, CLINIC_COORDINATOR |
| `/pat/commands/{id}` | DELETE | `pat.command.retire` | CAREGIVER, CLINIC_COORDINATOR |
| `/pat/gesture-types` | GET | `pat.gesture-type.read` | any authenticated `pat.*` actor + service clients |
| `/pat/gesture-types/{id}` | GET | `pat.gesture-type.read` | any authenticated `pat.*` actor + service clients |
| `/pat/gesture-types` | POST | `pat.gesture-type.create` | CLINIC_COORDINATOR |

Authority string definitions and role→authority mapping are canonical in **SPEC-06**.
No PAT endpoint is public; a `patient-session` token is rejected `403` on every path (INV-PAT-7).

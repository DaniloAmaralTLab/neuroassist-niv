# EVNT — API Contract

> Service: `evnt-service` · Module **EVNT — Events and Alarms** · Project: NeuroAssist NIV
> Stack: Java 21 / Spring Boot (hexagonal — `../../../adr/ADR-001-hexagonal-architecture.md`,
> key `hexagonal_java`) · Multi-tenant (schema-per-tenant) · Messaging disabled.
> EARS authoring guide: `../../../standards/ears-notation.md`.
> **This file is the FE hard barrier:** every endpoint below carries method, path, authority and
> status codes. The frontend (`evnt-ui` / DASH) builds against this surface and nothing else.

EVNT plays **three security roles** (ADR-006 adds the third). On the **device path** it is an **EDGE
resource server**: it validates the inbound `edge.device` token against EDGE JWKS + introspection
(ADR-002 local). On the **caregiver paths** it is an **ACS resource server**: it validates
ACS-issued caregiver JWTs against ACS JWKS. On the **detection-lapse ingest path** (§10, ADR-006) it
is also an **ACS resource server** but for an ACS-issued **service-client** JWT (principal
`edge-service`), never the `edge.device` station token. Tenant context on every authenticated endpoint
derives from the JWT `tenantId` claim (INV-EVNT-1); `X-Tenant-Id` is never trusted.

---

## 0. Conventions

- **Base path:** `/evnt`. GWY (API Gateway) fronts the service; paths below are as seen by the
  controller.
- **Media type:** `application/json`. Errors use `application/problem+json` (RFC 7807).
- **Identifiers:** all resource ids are UUID (string, canonical form) except `reportId` (station
  string key).
- **Authority model:** fine-grained authorities follow `evnt.<resource>.<action>` (D-639), sourced
  from the single `RoleAuthorityPolicy` (SPEC-06). Controller `@PreAuthorize` strings MUST equal
  those constants. Canonical English actions only: on the `event` resource `ingest`, `read`,
  `confirm`, `record`; on the `subscription` resource the canonical CRUD actions `create`, `delete`;
  on the `escalation` resource `read`; on the `detection-lapse` resource `create` (raise — `raise` is
  not a listed op verb, so the raise op is the canonical `create`), `resolve`, `read`, and `confirm`
  (caregiver acknowledgement — the same human-ack shape as `evnt.event.confirm`) — never `.view` /
  `.edit` / `.register` / `.raise` / `.acknowledge`.
- **State-changing verbs** map to `POST` only for the domain actions (`confirm`, `record`, `ingest`,
  and for `detection-lapse` the `create` raise + `resolve` + `confirm` acknowledgement — all `POST`);
  the `subscription` resource is a plain CRUD lifecycle so it uses `POST` to create and `DELETE` to
  remove (op verbs `create` / `delete` — SPEC-11). `GET` is side-effect free.

### 0.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `Authorization: Bearer <jwt>` | request | Required on every endpoint **except** `GET /evnt/health` (public). The device path requires an `edge.device` token; caregiver paths require an ACS caregiver token. |
| `X-Correlation-Id` | request/response | Propagated end-to-end; generated by GWY if absent; echoed on the response and on every HIST audit call. |
| `X-Tenant-Id` | — | **Never trusted from the request.** Tenant context is derived from the JWT `tenantId` claim only (INV-EVNT-1). |

EARS — headers & auth:

- WHEN a protected EVNT endpoint receives a request without a valid `Authorization` bearer token, THE SYSTEM SHALL respond `401 Unauthorized`.
- IF a request supplies an `X-Tenant-Id` header, THEN THE SYSTEM SHALL ignore it and derive tenant context exclusively from the JWT `tenantId` claim (INV-EVNT-1).
- IF the device path receives a caregiver token, or a caregiver path receives an `edge.device` token, THEN THE SYSTEM SHALL respond `401 Unauthorized` (wrong issuer for the path, INV-EVNT-6).
- THE SYSTEM SHALL echo the received `X-Correlation-Id` on every response and on every downstream HIST audit call.

### 0.2 Token types consumed

| Token | Issuer | `actorType` | Used on | Validated via |
|---|---|---|---|---|
| `edge.device` | EDGE | `edge-device` | §2 gesture-report ingest | EDGE JWKS (`/edge/.well-known/jwks.json`) + EDGE introspection (`POST /edge/device-tokens/introspect`) |
| caregiver | ACS | `caregiver` | §3 read, §4 confirm, §5 feedback, §6 subscriptions, §11–12 detection-lapse read/ack | ACS JWKS (+ ACS introspect on revoke-sensitive ops) |
| service-client (`edge-service`) | ACS | `service-client` | §10 detection-lapse raise/resolve (ADR-006) | ACS JWKS; principal `edge-service`; **never** the `edge.device` token |

## 2. Gesture-report ingest (device path — EDGE resource server)

### 2.1 `POST /evnt/gesture-reports` — ingest a recognized command (authority `evnt.event.ingest`)

Closes G5 / INT-EDGE-001 (ADR-002 local). The edge station reports the recognized `commandId` it
resolved locally (offline catalog — GEST/EDGE truth); EVNT generates exactly one `Event`, snapshots
`urgency` + `label` from PAT (ADR-004 local), and audits `EventGenerated`. `deviceId`, `patientId`,
`tenantId` are taken from the token claims, **never** from the body (INV-EVNT-6).

Request:

```json
{
  "commandId": "<uuid>",
  "reportId": "station-7f3a-00912",
  "occurredAt": "2026-11-20T08:14:03Z",
  "confidence": 0.92,
  "recognitionWindowMs": 640
}
```

- `commandId`, `reportId`, `occurredAt` are **required**. `confidence` (0..1) and
  `recognitionWindowMs` (int ≥ 0) are **optional**, stored verbatim in `report_meta` for later
  tuning and **never** used to branch v1 logic (resolved gap — §gesture-report schema below).

Response `201 Created` (+ `Location: /evnt/events/{id}`) — a new event:

```json
{ "id": "<uuid>", "tenantId": "<uuid>", "patientId": "<uuid>", "commandId": "<uuid>",
  "commandLabel": "water", "urgency": "emergency", "deviceId": "<uuid>",
  "reportId": "station-7f3a-00912", "occurredAt": "2026-11-20T08:14:03Z",
  "confirmedAt": null, "confirmedBy": null, "feedback": "not_evaluated",
  "createdAt": "2026-11-20T08:14:03Z" }
```

Response `200 OK` — idempotent replay of a consumed `(deviceId, reportId)`: the **existing** event
body (no second audit — INV-EVNT-4).

EARS:

- WHEN a valid `edge.device` token carrying `evnt.event.ingest` reports a `commandId` resolvable in PAT for the first time with its `(deviceId, reportId)`, THE SYSTEM SHALL resolve `urgency` + `commandLabel` from PAT, persist one `Event`, respond `201 Created`, and audit `EventGenerated` within the same request.
- WHEN a report replays a `(deviceId, reportId)` already consumed, THE SYSTEM SHALL return the existing event `200 OK` and SHALL NOT create a second event nor a second audit (INV-EVNT-4).
- THE SYSTEM SHALL take `deviceId`, `patientId`, `tenantId` from the token claims and SHALL ignore any of these supplied in the body (INV-EVNT-6).
- IF `commandId`, `reportId` or `occurredAt` is absent or malformed, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.
- IF `occurredAt` is in the future beyond a 5-minute skew or older than 24h, THEN THE SYSTEM SHALL respond `400 Bad Request` type `occurred-at-out-of-bounds`.
- IF the `edge.device` token is absent, expired, signature-invalid, or introspection reports it revoked/unpaired, THEN THE SYSTEM SHALL respond `401 Unauthorized` (INV-EVNT-6).
- IF the token lacks `evnt.event.ingest`, THEN THE SYSTEM SHALL respond `403 Forbidden`.
- IF `{commandId}` is not found in the device's tenant at PAT (`GET /pat/commands/{commandId}` → `404`), THEN THE SYSTEM SHALL respond `404 Not Found` type `command-not-found` and SHALL NOT create an event.
- IF PAT is unreachable or errors at generation, THEN THE SYSTEM SHALL respond `503 Service Unavailable` type `catalog-unavailable` with `Retry-After`, SHALL NOT create an event, and SHALL NOT guess urgency (fail-closed — ADR-004, Risk R4).
- IF the HIST audit write fails after the event is persisted, THEN THE SYSTEM SHALL keep the persisted event and enqueue the audit envelope for idempotent durable retry (HIST ADR-005: `EventGenerated` is commit+durable-retry — the help-request pathway must never be blocked by an audit outage); dev: log-only (event-contracts §1, hist-service event-contracts §3).
- WHERE two reports race on the same unconsumed `(deviceId, reportId)`, THE SYSTEM SHALL let the DB UNIQUE arbitrate and resolve the loser to the `200` replay path (`409` from the DB is mapped to the winner's event — SPEC-05), so the caller never sees a raw `409`.

## 3. Read surface (caregiver path — ACS resource server, pull-based delivery ADR-003)

All §3 reads are scoped by tenant **and** ACS caregiver↔patient link (INV-EVNT-7, resolved gap):
the caregiver id is the JWT `sub`; EVNT resolves the caller's linked patients via ACS
(`GET /acs/caregivers/{caregiverId}/links`, cached) and denies unlinked / cross-tenant patients
`404` (never disclose existence).

### 3.1 `GET /evnt/patients/{patientId}/active-alarm` — the active emergency (authority `evnt.event.read`)

The dashboard **polls** this endpoint (polling contract in SPEC-03). Returns the single active
emergency event (read-time query — INV-EVNT-3, ADR-010: `urgency = emergency AND confirmedAt IS
NULL`, newest by `occurredAt`) or an empty envelope.

Response `200 OK` — alarm present:

```json
{ "activeAlarm": { "id": "<uuid>", "patientId": "<uuid>", "commandId": "<uuid>",
  "commandLabel": "water", "urgency": "emergency", "occurredAt": "2026-11-20T08:14:03Z",
  "confirmedAt": null, "feedback": "not_evaluated" },
  "serverTime": "2026-11-20T08:14:05Z", "pollIntervalSeconds": 3 }
```

Response `200 OK` — no active alarm: `{ "activeAlarm": null, "serverTime": "...", "pollIntervalSeconds": 3 }`.

EARS:

- WHILE the patient has an unconfirmed `emergency` event, THE SYSTEM SHALL return it as `activeAlarm` on every poll until it is confirmed (INV-EVNT-3).
- WHEN the patient has no unconfirmed emergency, THE SYSTEM SHALL return `activeAlarm: null` `200 OK`.
- THE SYSTEM SHALL return `pollIntervalSeconds` so the client adopts the server-advertised cadence (SPEC-03) rather than hard-coding it.
- THE SYSTEM SHALL include `serverTime` so the client can detect clock skew and stale polling.
- IF the caller is not linked to `{patientId}` within their tenant, THEN THE SYSTEM SHALL respond `404 Not Found` (INV-EVNT-7).

### 3.2 `GET /evnt/patients/{patientId}/events` — recent events (authority `evnt.event.read`)

Query: `?urgency=emergency|routine|all` (default `all`), `?limit=` (default 50, max 200),
`?before=<iso8601>` (keyset page by `occurredAt`). Response `200 OK`:

```json
{ "events": [ { "id": "<uuid>", "commandLabel": "water", "urgency": "routine",
  "occurredAt": "2026-11-20T08:00:00Z", "confirmedAt": null, "feedback": "not_evaluated" } ],
  "nextBefore": "2026-11-20T07:40:00Z" }
```

- THE SYSTEM SHALL return only events of `{patientId}` within the caller's tenant, ordered `occurredAt DESC` (INV-EVNT-7).
- IF `limit` exceeds 200 or `before` is malformed, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.
- IF the caller is not linked to `{patientId}`, THEN THE SYSTEM SHALL respond `404 Not Found`.

### 3.3 `GET /evnt/events/{eventId}` — read one event (authority `evnt.event.read`)

Response `200 OK`: the full event body (as §2.1 `201`).

- IF `{eventId}` is cross-tenant or belongs to a patient the caller is not linked to, THEN THE SYSTEM SHALL respond `404 Not Found` (INV-EVNT-7) — existence is never disclosed.

### 3.4 `GET /evnt/events/{eventId}/escalation-attempts` — the out-of-band escalation trail (authority `evnt.escalation.read`)

Returns the escalation attempts recorded for an emergency event (SPEC-11): which tiers fired, when,
over which channel, and the outcome. Scoped by the same tenant + ACS link as the rest of §3
(INV-EVNT-7). Destinations are **masked** (last digits of a phone, a subscription label — never the
full endpoint/keys).

Response `200 OK`:

```json
{ "eventId": "<uuid>", "urgency": "emergency",
  "attempts": [
    { "tier": 0, "channel": "web_push", "caregiverId": "<uuid>", "target": "sub:chrome-…",
      "status": "sent",   "providerMessageId": "wp-…", "attemptedAt": "2026-11-20T08:14:03Z" },
    { "tier": 1, "channel": "sms",      "caregiverId": "<uuid>", "target": "+55•••••1234",
      "status": "failed", "errorReason": "no-contact", "attemptedAt": "2026-11-20T08:14:33Z" },
    { "tier": 2, "channel": "voice",    "caregiverId": "<uuid>", "target": "+55•••••1234",
      "status": "sent",   "providerMessageId": "vc-…", "attemptedAt": "2026-11-20T08:15:33Z" } ] }
```

EARS:

- THE SYSTEM SHALL return the escalation attempts for `{eventId}` ordered by `attemptedAt`, with destinations masked (SPEC-11, SPEC-06).
- IF the caller is not linked to the event's patient, THEN THE SYSTEM SHALL respond `404 Not Found` (INV-EVNT-7).

## 4. Confirmation (caregiver path)

### 4.1 `POST /evnt/events/{eventId}/confirmation` — acknowledge an emergency (authority `evnt.event.confirm`)

Explicit human acknowledgement of an emergency: sets `confirmedAt` + `confirmedBy` (JWT `sub`).
Body: empty (`{}`). Idempotent (INV-EVNT-5).

Response `200 OK`:

```json
{ "id": "<uuid>", "urgency": "emergency", "confirmedAt": "2026-11-20T08:14:12Z",
  "confirmedBy": "<caregiverId>", "feedback": "not_evaluated" }
```

EARS:

- WHEN a caregiver with `evnt.event.confirm`, linked to the event's patient, confirms an unconfirmed `emergency` event, THE SYSTEM SHALL set `confirmedAt = now()` and `confirmedBy = sub`, remove it from the active-alarm query, respond `200 OK`, and audit `AlarmConfirmed` within the same request.
- WHEN an already-confirmed emergency event is confirmed again, THE SYSTEM SHALL return `200 OK` with the existing `confirmedAt`/`confirmedBy` and SHALL NOT emit a second `AlarmConfirmed` (idempotent — INV-EVNT-5).
- IF the event's `urgency` is `routine`, THEN THE SYSTEM SHALL respond `409 Conflict` type `not-confirmable` (only emergencies are confirmable — INV-EVNT-5).
- IF the caller is not linked to the event's patient, THEN THE SYSTEM SHALL respond `404 Not Found`.

## 5. Feedback (caregiver path)

### 5.1 `POST /evnt/events/{eventId}/feedback` — record a verdict (authority `evnt.event.record`)

A caregiver's later verdict on any event, independent of confirmation (two axes — doc 03).

Request: `{ "verdict": "real" }` — `verdict ∈ { real, false_positive }`.

Response `200 OK`: `{ "id": "<uuid>", "feedback": "real" }`.

EARS:

- WHEN a caregiver with `evnt.event.record`, linked to the event's patient, records `real` or `false_positive`, THE SYSTEM SHALL set `feedback`, respond `200 OK`, and audit `FeedbackRecorded` within the same request.
- WHEN the same verdict is recorded again, THE SYSTEM SHALL return `200 OK` and SHALL NOT emit a second `FeedbackRecorded` (idempotent — SPEC-05); a **changed** verdict overwrites and audits once.
- IF `verdict` is absent or not in the enum, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.
- IF the caller is not linked to the event's patient, THEN THE SYSTEM SHALL respond `404 Not Found`.

## 6. Push subscriptions (caregiver path — out-of-band Tier 0, ADR-005 / SPEC-11)

A caregiver's browser/PWA obtains a Web Push subscription (VAPID) and registers it here so EVNT can
reach them when the dashboard is backgrounded. The subscription `endpoint` + `keys` come from the
browser Push API; EVNT stores them (`push_subscription`, data-model §2.2) and uses them as the Tier 0
channel. The VAPID **public** key is served to the client via app config (not an EVNT endpoint in v1).

### 6.1 `POST /evnt/push-subscriptions` — register a subscription (authority `evnt.subscription.create`)

Request:

```json
{ "endpoint": "https://fcm.googleapis.com/fcm/send/…",
  "keys": { "p256dh": "<base64url>", "auth": "<base64url>" },
  "userAgent": "Chrome/141 on Android" }
```

- `endpoint` and `keys.p256dh` / `keys.auth` are **required**; `userAgent` optional (diagnostics).
- `caregiverId` and `tenantId` come from the JWT (`sub` / `tenantId`), **never** the body.

Response `201 Created` — new subscription: `{ "id": "<uuid>", "createdAt": "…" }`
(+ `Location: /evnt/push-subscriptions/{id}`). Response `200 OK` — idempotent re-register of the same
`(tenantId, endpoint)`: the existing `{ "id": "…" }` (the browser may re-send the same subscription).

EARS:

- WHEN a caregiver registers a well-formed subscription for the first time for its `(tenantId, endpoint)`, THE SYSTEM SHALL persist it against the caller's `caregiverId` and respond `201 Created`.
- WHEN the same `(tenantId, endpoint)` is registered again, THE SYSTEM SHALL return the existing subscription `200 OK` and SHALL NOT create a duplicate row.
- THE SYSTEM SHALL take `caregiverId`/`tenantId` from the JWT and SHALL ignore any supplied in the body (INV-EVNT-1).
- IF `endpoint` or either key is absent or malformed, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.

### 6.2 `DELETE /evnt/push-subscriptions/{subscriptionId}` — remove a subscription (authority `evnt.subscription.delete`)

Response `204 No Content`. Idempotent for the caller's own rows.

EARS:

- WHEN a caregiver deletes a subscription they own, THE SYSTEM SHALL remove it and respond `204 No Content`.
- IF `{subscriptionId}` does not exist or is not owned by the caller (different `caregiverId`/tenant), THEN THE SYSTEM SHALL respond `404 Not Found` (existence not disclosed, INV-EVNT-7 posture).

## 8. Error surface (RFC 7807 ProblemDetail)

All errors return `application/problem+json` with a stable `type` URI, the HTTP `status`, a `title`,
a `detail`, and the request `correlationId`.

| `type` | HTTP | Raised on |
|---|---|---|
| `validation-error` | 400 | malformed body / bad enum / bad query param |
| `occurred-at-out-of-bounds` | 400 | `occurredAt` outside the accepted skew window (§2.1) |
| `unauthorized` | 401 | missing/expired/invalid token, wrong issuer for the path, revoked device |
| `forbidden` | 403 | authenticated but missing the required authority |
| `not-found` | 404 | cross-tenant / unlinked patient / unknown event (existence not disclosed) |
| `command-not-found` | 404 | `{commandId}` not in tenant at PAT (§2.1) |
| `not-confirmable` | 409 | confirm attempted on a `routine` event (§4.1) |
| `catalog-unavailable` | 503 | PAT unreachable at ingest — fail-closed, station retries (§2.1) |
| `audit-unavailable` | 502 | HIST audit write failed (prod policy — §2.1 TODO) |

EARS — error surface:

- THE SYSTEM SHALL return `application/problem+json` with a stable `type` URI, the HTTP `status`, and the request `correlationId` for every error response.
- THE SYSTEM SHALL NOT distinguish "event does not exist" from "event exists but caller is unlinked / cross-tenant": both are `404 not-found` (INV-EVNT-7, anti-enumeration).

## 9. Resolved open questions (specs decisions)

| Vision open item (doc 06) | Specs decision |
|---|---|
| Gesture-report schema — carry confidence/timing? | **Yes, optional & non-authoritative.** `confidence` + `recognitionWindowMs` accepted and persisted in `report_meta` (jsonb, nullable); required core stays `{commandId, reportId, occurredAt}`; v1 never branches on them (keeps schema stable while preserving future tuning — SPEC-02). |
| Read scoping — tenant-only vs tenant + ACS link? | **Tenant + ACS caregiver↔patient link** (INV-EVNT-7). EVNT resolves the caller's links via ACS; unlinked/cross-tenant → `404`. Family tenants are trivially covered; clinic tenants require the link check. |
| Degrade when PAT unavailable at ingest | **Fail-closed** — `503 catalog-unavailable` + `Retry-After`, no event, no guess (ADR-004, R4). The station's at-least-once retry re-drives ingest. |
| HIST audit envelope | **Identical envelope to ACS/PAT/EDGE** (event-contracts §1.1); `action` discriminates. Failure policy prod `502` / dev log-only, TODO confirm enqueue. |
| SAFETY-1 — out-of-band delivery to a backgrounded/offline caregiver | **Closed by design (ADR-005, product decision 2026-11-20).** Escalation Web Push → SMS → voice runs inside EVNT (SPEC-11), stopping on confirmation; new surface §3.4 (read attempts) + §6 (register/remove a push subscription). Residual limits (no cellular coverage, provisioning) stated in SPEC-03. |
| SAFETY-GEST-1 — station connected but not detecting | **Owned by EVNT alerting (ADR-006, product decision 2026-11-20).** EDGE raises a detection lapse (§10 service-client ingest); EVNT surfaces a distinct caregiver alert (§11 list) + reuses the SPEC-11 ladder (push→SMS→voice) until **resolved** (EDGE) or **acknowledged** (§12); a real emergency always outranks a lapse (SPEC-12 LAPSE-6). Residual limits identical to SAFETY-1. |

## 10. Detection-lapse ingest (service-client path — EDGE backend → EVNT, ADR-006 / SPEC-12)

A **backend-to-backend** path distinct from §2 (which is the station's `edge.device` gesture report).
When the EDGE lapse sweep opens a detection-lapse episode (patient station connected but not detecting,
or heartbeat stopped, for `N` s — EDGE ADR-005), **EDGE** raises it here with an **ACS-issued
service-client JWT** for the `edge-service` principal. EVNT owns the alerting/escalation (SPEC-12).
`deviceId`/`patientId`/`tenantId` are read from the payload of this **trusted service-client** call
(not from a station token).

### 10.1 `POST /evnt/detection-lapses` — raise a detection lapse (authority `evnt.detection-lapse.create`)

Headers: `Idempotency-Key: <stable per-episode key>` (**required**) + `X-Correlation-Id`. Request:

```json
{
  "deviceId": "<uuid>",
  "patientId": "<uuid>",
  "tenantId": "<uuid>",
  "cause": "NOT_RUNNING",
  "detectionState": "PAUSED",
  "reason": "HIDDEN",
  "lastDetectingAt": "2026-11-20T08:10:00Z",
  "lapseStartedAt": "2026-11-20T08:12:00Z",
  "engineVersion": "1.4.2"
}
```

- `deviceId`, `patientId`, `tenantId`, `cause`, `lapseStartedAt` are **required**; `detectionState`,
  `reason`, `lastDetectingAt`, `engineVersion` optional.
- `cause ∈ { NOT_RUNNING, HEARTBEAT_STOPPED }`;
  `detectionState ∈ { RUNNING, PAUSED, DEGRADED, UNAVAILABLE, UNKNOWN }` (valid Java identifiers).

Response `201 Created` (+ `Location: /evnt/detection-lapses/{id}`) — a new open episode:

```json
{ "id": "<lapseId>", "tenantId": "<uuid>", "patientId": "<uuid>", "deviceId": "<uuid>",
  "cause": "NOT_RUNNING", "detectionState": "PAUSED", "status": "open",
  "lapseStartedAt": "2026-11-20T08:12:00Z", "createdAt": "2026-11-20T08:12:01Z" }
```

Response `200 OK` — idempotent replay of a consumed `(tenantId, Idempotency-Key)`: the **existing**
lapse body (open, resolved or acknowledged), no second escalation start, no second audit.

EARS:

- WHEN a valid `edge-service` service-client token carrying `evnt.detection-lapse.create` raises a lapse with a first-seen `(tenantId, Idempotency-Key)`, THE SYSTEM SHALL persist one `detection_lapse` `status=open`, respond `201 Created`, and audit `DetectionLapseRaised` (SPEC-12 LAPSE-1/LAPSE-7).
- WHEN a raise replays a consumed `(tenantId, Idempotency-Key)`, THE SYSTEM SHALL return the existing lapse `200 OK` and SHALL NOT start a second escalation nor a second audit — even if the lapse is already resolved/acknowledged (ordering safety — LAPSE-2).
- IF the token is not an `edge-service` service-client token (e.g. an `edge.device` station token), THEN THE SYSTEM SHALL respond `401 Unauthorized`; IF it lacks `evnt.detection-lapse.create`, THEN `403 Forbidden`.
- IF a required field is absent or `cause`/`detectionState` is outside its enum, THEN THE SYSTEM SHALL respond `400 Bad Request` type `validation-error`.

### 10.2 `POST /evnt/detection-lapses/{lapseId}/resolution` — resolve a lapse (authority `evnt.detection-lapse.resolve`)

EDGE calls this on the device's first `RUNNING` heartbeat (station recovered). Same service-client
identity. Body: empty (`{}`). Idempotent. Response `200 OK`:

```json
{ "id": "<lapseId>", "status": "resolved", "resolvedAt": "2026-11-20T08:15:00Z" }
```

EARS:

- WHEN EDGE resolves an open lapse, THE SYSTEM SHALL set `resolved_at = now()`, stop escalation (next sweep fires no further tier — LAPSE-5), respond `200 OK`, and audit `DetectionLapseResolved`.
- WHEN a resolve replays an already-resolved lapse, THE SYSTEM SHALL return `200 OK` and SHALL NOT audit a second `DetectionLapseResolved`.
- IF `{lapseId}` is unknown, THEN THE SYSTEM SHALL respond `404 Not Found` (EDGE keeps its episode open and retries — EDGE integration-contracts §6.2).

## 11. Detection-lapse read (caregiver path — ACS resource server, ADR-006 / SPEC-12)

### 11.1 `GET /evnt/patients/{patientId}/detection-lapses` — the distinct "station not detecting" list (authority `evnt.detection-lapse.read`)

Query: `?status=open|all` (default `open`). This is a **separate** surface from the emergency
`active-alarm` (§3.1): a lapse is never rendered as an emergency (LAPSE-3). Scoped by tenant + ACS link
(INV-EVNT-7). Response `200 OK`:

```json
{ "patientId": "<uuid>",
  "lapses": [
    { "id": "<lapseId>", "deviceId": "<uuid>", "cause": "NOT_RUNNING", "detectionState": "PAUSED",
      "status": "open", "lapseStartedAt": "2026-11-20T08:12:00Z",
      "acknowledgedAt": null, "resolvedAt": null } ] }
```

EARS:

- THE SYSTEM SHALL return the detection lapses of `{patientId}` in the caller's tenant, newest first, filtered by `status` (INV-EVNT-7, LAPSE-3).
- IF the caller is not linked to `{patientId}`, THEN THE SYSTEM SHALL respond `404 Not Found`.

## 12. Detection-lapse acknowledgement (caregiver path — ADR-006 / SPEC-12)

### 12.1 `POST /evnt/detection-lapses/{lapseId}/confirmation` — acknowledge a lapse alert (authority `evnt.detection-lapse.confirm`)

A linked caregiver acknowledges the "station not detecting" alert (op `acknowledgeDetectionLapse`,
modelled with the canonical `confirm` verb — same human-ack-stops-escalation shape as §4.1). Body:
empty (`{}`). Idempotent. Response `200 OK`:

```json
{ "id": "<lapseId>", "status": "acknowledged",
  "acknowledgedAt": "2026-11-20T08:13:30Z", "acknowledgedBy": "<caregiverId>" }
```

EARS:

- WHEN a caregiver linked to the lapse's patient acknowledges an open lapse, THE SYSTEM SHALL set `acknowledged_at`/`acknowledged_by = sub`, stop escalation (LAPSE-5), respond `200 OK`, and audit `DetectionLapseAcknowledged`.
- WHEN an already-acknowledged (or resolved) lapse is acknowledged again, THE SYSTEM SHALL return `200 OK` and SHALL NOT audit a second `DetectionLapseAcknowledged` (idempotent).
- IF the caller is not linked to the lapse's patient, THEN THE SYSTEM SHALL respond `404 Not Found`.

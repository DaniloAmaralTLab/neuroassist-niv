## Contexto

Two related security infrastructure components:

**JwtBlacklistAdapter**: implements `TokenBlacklistPort` by delegating to
`JwtBlacklistRepositoryAdapter` (ACS-014). Called from:
- `PatientSessionService.revoke` (write, within the same transaction — ACS-009)
- A Servlet filter `BlacklistCheckFilter` (read, on every protected request).

**BlacklistCheckFilter**: runs early in the filter chain (after JWT decoding) to check if
the `jti` from the validated JWT is blacklisted. If blacklisted → reject with 401 before
the request reaches the controller. This is the enforcement side of INV-4.

**CorrelationIdFilter**: the ONLY correlation ID filter — a Servlet `@Order(HIGHEST_PRECEDENCE)`
filter that sets `MDC.put("correlationId", ...)` and echoes it on the response header.
Do NOT also create a `CorrelationIdInterceptor` (Spring MVC interceptor) — both would run
and produce duplicate headers + MDC leaks (pitfall
`scaffold:infrastructure-security:duplicate-correlation-id-mdc`).

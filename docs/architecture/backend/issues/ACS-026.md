# ACS-026 -- Extend durable audit retry to CaregiverAuthenticated + PatientUnlinked (HIST ADR-005)

**Status:** INTACT -- gerado 2026-11-20
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

HIST ADR-005 (accepted, Option B) moves two more ACS facts into the **commit+durable-retry** set:
`CaregiverAuthenticated` (SAFETY — a caregiver must be able to log in to attend an active alarm; W1
ratified) and `PatientUnlinked` (ACCESS-END — removes a link). ACS already has the durable-retry
mechanism (ACS-016 `HistAuditPortAdapter` + ACS-024 `AuditRetryQueue`/`AuditRetryScheduler`) for the
SEC-001 access-ending facts (`PatientSessionRevoked`, `CaregiverDeactivated`). This issue **extends**
that mechanism to the two newly added facts — no new queue, just routing these two actions through it.

Durable-retry contract (HIST event-contracts §3): commit-first, local durable queue, idempotent
replay with an explicit `idempotencyKey` (ADR-003), bounded with backoff + a backlog alert, dev
log-only.

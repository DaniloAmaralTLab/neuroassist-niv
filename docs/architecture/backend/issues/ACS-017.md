# ACS-017 -- SecurityConfig — JWT resource server + @EnableMethodSecurity + JwtGrantedAuthoritiesConverter (permissions claim, no SCOPE_ prefix) + TenantContextFilter inside SecurityFilterChain

## Contexto

The Spring Security configuration that guards all ACS endpoints. Four known pitfalls to
pre-empt:

1. **`@EnableMethodSecurity` missing** (pitfall `security-config:missing-enable-method-security`):
   without it, every `@PreAuthorize` is silently ignored and any authenticated token passes.

2. **JwtGrantedAuthoritiesConverter mismatch** (pitfall `security:jwt-authorities-converter-missing`):
   the converter must read from claim `permissions` (not `scope`/`scp`) with an **empty prefix**;
   otherwise `hasAuthority("acs.caregiver.create")` never matches because Spring adds the
   `SCOPE_` prefix.

3. **TenantContextFilter early registration** (pitfall `security:tenant-context-filter:early-registration-before-jwt-processing`):
   `TenantContextFilter` must be registered inside the `SecurityFilterChain` via
   `http.addFilterAfter(filter, BearerTokenAuthenticationFilter.class)`, NOT as `@Component`
   with `@Order` — a Servlet-registered filter runs before the JWT filter, sees an empty
   `SecurityContext` and fails to resolve the tenant.

4. **Actuator health paths** (pitfall `security:actuator-health-probes:exact-path-permitall-401s-liveness-readiness`):
   use `"/actuator/health/**"` (wildcard), not `/actuator/health` (exact match).

Also: `@EnableMethodSecurity` enables the Spring Security proxy for `@PreAuthorize` —
confirm that the `AccessDeniedException` re-throw is in `GlobalExceptionHandler` (ACS-020)
to avoid `403 → 500` drift (pitfall `api-exception-handler:access-denied-captured-by-generic`).

# ACS-024 -- Async retry queue for access-ending HIST audit failures (SEC-001 — revocation + deactivation never blocked by audit outage)

## Contexto

The `AuditRetryQueue` stores audit envelopes that failed during access-ending operations
(PatientSessionRevoked, CaregiverDeactivated) and retries them asynchronously
(event-contracts §1.2, SEC-001: "the access change must not be blocked by an audit-sink
outage"). The local state change and the blacklist entry are always committed first;
the audit follows on a best-effort basis.

Implementation options:
- Simple in-memory queue with `@Scheduled` retry (acceptable for MVP pilot volume).
- Persistent queue (database table `acs_pending_audit`) for durability across restarts.
  Recommended for production — aligns with SEC-001 audit guarantee.

For MVP: an in-memory `LinkedBlockingQueue<AuditEnvelope>` with a `@Scheduled` retry every
30s, backed by a persistent fallback table when the queue is full or on restart.
`AuditRetryScheduler` reads from the queue and retries the `HistClient.postAudit` call.

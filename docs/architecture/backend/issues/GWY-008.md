# GWY-008 -- CorsWebFilter — explicit caregiver-shell origin allow-list, never wildcard+credentials, exposed X-Correlation-Id (ADR-004, Risk R6)

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

Configures CORS for the Angular caregiver shell. A wildcard origin (`*`) combined with
`allow-credentials: true` would expose the shell to any website (Risk R6). The origin
list is explicit and per-environment. Allowed methods are `GET, POST, DELETE, OPTIONS`;
allowed headers include `Authorization` and `X-Correlation-Id`; exposed header
`X-Correlation-Id` so the browser can read it. Browser `OPTIONS` preflights are
answered at the edge without reaching a downstream. Implemented as a `CorsWebFilter`
bean in a dedicated `CorsConfig` class (not inside `SecurityConfig`).

## Resultado esperado

A `CorsWebFilter` bean that reads origin list from `gateway.cors.allowed-origins`,
allows the configured methods and headers, exposes `X-Correlation-Id`, and structurally
prevents wildcard-with-credentials.

## Criterios de aceite

- [ ] AC-1 `CorsConfig` reads `gateway.cors.allowed-origins` from configuration (not hard-coded)
- [ ] AC-2 `allow-credentials: true` is set only alongside an explicit non-wildcard origin list (never `*` + credentials, Risk R6)
- [ ] AC-3 `GET, POST, DELETE, OPTIONS` are the allowed methods
- [ ] AC-4 `X-Correlation-Id` appears in both `allowed-headers` and `exposed-headers`

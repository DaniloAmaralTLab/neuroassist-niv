# REG-008 -- Implement structured lifecycle logging for registration, renewal, and eviction events to Elasticsearch

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/5 itens

## Contexto
REG must emit a structured lifecycle log entry for each registration, renewal, and eviction event. These logs are shipped best-effort to the platform Elasticsearch cluster. If Elasticsearch is unavailable, REG continues serving registrations and discovery unaffected (SPEC-10 resilience).

## Spec de referencia
- SPEC-07 (Observability and Health — lifecycle logging)
- SPEC-10 (Integrations — outbound observability stack)

## Escopo
- [ ] implementar `src/main/java/com/neuroassist/registry/config/LoggingConfig.java` — `@Configuration` that registers a `com.netflix.eureka.resources.EurekaResource` listener (or `EurekaEventListener`) logging `{event: "REGISTERED|RENEWED|CANCELLED", app: appId, instanceId: instanceId}` as structured JSON to SLF4J
- [ ] implementar `src/main/resources/logback-spring.xml` — JSON layout (Logstash encoder or plain JSON appender) for the `com.neuroassist.registry` logger; best-effort async appender; configure ship-to-Elasticsearch or leave as stdout JSON for sidecar collection
- [ ] implementar `src/test/java/com/neuroassist/registry/LifecycleLoggingTest.java` — assert that a registration event produces a log entry with `event=REGISTERED` and correct `app`/`instanceId` fields (use `ListAppender<ILoggingEvent>`)

## Criterios de aceite
- [ ] AC-1: `./gradlew :services:neuroassist-niv-service-registry:test` exits 0 (LifecycleLoggingTest passes)
- [ ] AC-2: Running locally and registering a mock client produces a JSON log line containing `"event":"REGISTERED"` and the client's logical id
- [ ] AC-3: Stopping Elasticsearch (or setting an unreachable log destination) does not prevent `/eureka/apps` from responding correctly
- [ ] AC-4: Log entries contain no PHI fields; only `app`, `instanceId`, `host`, `port`, and event type are logged

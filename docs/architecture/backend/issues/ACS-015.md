## Contexto

ACS authors two Flyway migration files; MIG applies them centrally (ACS does NOT run
Flyway at start — setup-local.md §Commands). Migration ranges are reserved to avoid
collision (data-model §5):
- `V0010__acs_global_init.sql` → applied to `neuroassist_global` schema: creates
  `pgcrypto` extension, `tenant`, `caregiver_identity_lookup`, `jwt_blacklist` tables.
- `V0011__acs_tenant_init.sql` → applied to each `t_<tenantId>` schema at onboarding:
  creates `caregiver`, `caregiver_patient_link`, `patient_session` tables.

Important: table names must be prefixed with the module code where they overlap a
common name (pitfall `multitenancy:shared-schema:generic-table-name-collision`) — however,
ACS table names are domain-specific enough to not collide. The `-- schema:` routing
comment on the first line of each block is mandatory for the MIG driver.

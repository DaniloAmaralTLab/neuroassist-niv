## Contexto

Revocation must be immediate and not blockable by an audit outage (SEC-001). The
sequence:
1. Load `PatientSession` by id (tenant-scoped); if status already `REVOKED`, return 204
   idempotently — no second blacklist entry (SPEC-05, event-contracts §3).
2. Set `status = REVOKED`, `revokedBy`, `revokedAt` and add `token_jti` to
   `jwt_blacklist` **in the same `@Transactional` block**.
3. After commit, call `HistAuditPort.recordAccessEndingAction(PatientSessionRevoked, ...)`.
   If HIST is unreachable, the local state change is already committed; the audit is
   enqueued for retry (access-ending contract, event-contracts §1.2, ACS-024).
The domain invariant check for INV-4 (`chk_session_revoked_consistency`) is enforced
both in the domain model and by the DB constraint.

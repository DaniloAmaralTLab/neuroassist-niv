## Contexto

JPA entities for all 6 tables in `data-model.md`. Key design notes:
- **Schema-per-tenant:** per-tenant entities (`caregiver`, `caregiver_patient_link`,
  `patient_session`) carry `tenant_id` for defence-in-depth and audit joins, but no
  `findByTenantId` query method in the port interfaces (D-534, schema routing by
  data-source, not column).
- **No tenantId parameter in repository ports** — the per-tenant data source is activated
  by a request-scoped tenant context resolver (not by explicit column filter).
- **Enums stored as `varchar` + CHECK:** use `@Enumerated(EnumType.STRING)` with
  `@Column(columnDefinition = "varchar(N)")`.
- **UUID PK with `Persistable<UUID>`:** `isNew()` based on `@Transient boolean newEntity`
  reset by `@PostLoad` — avoids Hibernate detached entity error on save (pitfall
  `jpa-entity:generated-value-preassigned-uuid:hibernate6-detached-entity-error`).
- **No cross-schema FK:** `patient_id` and `device_id` on `patient_session` and
  `caregiver_patient_link` are plain UUID columns (no JPA @ManyToOne to PAT/EDGE entities).

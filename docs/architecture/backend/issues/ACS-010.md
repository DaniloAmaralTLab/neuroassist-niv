## Contexto

Two lifecycle operations for the `Caregiver` aggregate:

**Register:** caller is CLINIC_COORDINATOR. The service creates both:
- the `caregiver` row (per-tenant, with `tenant_id = caller.tenantId`),
- the `caregiver_identity_lookup` row (global, for future login resolution — INV-6).
If the `username` already exists globally (lookup PK), respond 409 `username-taken`.
Tenant is derived from the authenticated caller's JWT, never from the request body (INV-1).
Audit: `CaregiverRegistered` via `HistAuditPort` (grant action — rollback on HIST failure).

**Deactivate:** soft delete — sets `status = DEACTIVATED`, row retained. Caller is
CLINIC_COORDINATOR. If the target caregiver belongs to a different tenant, return 404 (no
cross-tenant disclosure). Audit: `CaregiverDeactivated` (access-ending action — enqueue on
HIST failure, SEC-001).

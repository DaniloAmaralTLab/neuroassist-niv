# ACS-020 -- GlobalExceptionHandler — ResponseEntity<ProblemDetail> for all handlers + explicit AccessDeniedException re-throw (avoid 403->500 drift)

**Status:** INTACT -- gerado 2026-11-19
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

The `@RestControllerAdvice` that maps all domain/security exceptions to RFC 7807
`application/problem+json` responses.

Two known pitfalls:

1. **Bare ProblemDetail returns HTTP 500** (pitfall `exception-handler:plain-problem-detail:wrong-http-status`):
   every `@ExceptionHandler` method MUST return `ResponseEntity<ProblemDetail>` with
   `pd.setStatus(statusCode)` called explicitly and `ResponseEntity.status(statusCode)` on
   the builder. A handler returning bare `ProblemDetail` falls back to HTTP 500 for all
   codes because `ProblemDetailFactory.CODE_METADATA` is not auto-wired.

2. **AccessDeniedException captured by generic handler** (pitfall `api-exception-handler:access-denied-captured-by-generic:403-becomes-500`):
   after `@EnableMethodSecurity` is activated, a `@PreAuthorize` failure throws
   `AccessDeniedException` (or `AuthorizationDeniedException`). If the generic
   `Exception.class` handler catches it first, it returns 500. The fix: add an explicit
   `@ExceptionHandler(AccessDeniedException.class)` that **re-throws** the exception, so
   the Spring Security `ExceptionTranslationFilter` handles it and returns 403.

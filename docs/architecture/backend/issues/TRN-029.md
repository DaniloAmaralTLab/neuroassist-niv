# TRN-029 -- Idempotency hardening — application-layer idempotency guard for publication; unique constraints on publication (tenant_id+approval_id) and outbound_job (tenant_id+job_type+idempotency_key) upsert-safe (SPEC-05, INV-TRN-6, data-model §2.8/§2.9)

## Contexto
Add an application-layer idempotency guard for publication: detect a repeat `POST /trn/proposals/{id}/publication` for a known `approvalId` and return the existing `Publication` record (`202`/`200`) without enqueuing duplicate jobs. Covers the two unique constraints from data-model.md §2.8 (`tenant_id + approval_id` and `tenant_id + idempotency_key` on `publication`). Also validates that `outbound_job` constraints (`tenant_id + job_type + idempotency_key`) make job retries safe from duplicate enqueues (upsert-on-conflict instead of insert).

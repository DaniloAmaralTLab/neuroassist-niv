# MIG-023 -- Dockerfile + docker-compose init service with restart:no (SPEC-07, doc 06 R7)

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

The migrator job runs as an init/batch container before the fleet starts. Its docker-compose service entry MUST use restart:no (doc 06 R7): a restart policy would retry on failure, masking real migration errors and potentially starting the fleet against a half-migrated database. The job's non-zero exit code is the signal that ops must act on.

## Spec de referencia
- SPEC-07 (restart:no, batch job contract)
- contracts/api-contract.md §5 (exit codes)

## Escopo
- `services/neuroassist-niv-migrations/Dockerfile` — multi-stage: builder (Gradle build) + JRE runtime stage; copies the fat JAR; ENTRYPOINT java -jar
- `docker-compose.yml` (backend root) — migrations service entry: image, restart:no, depends_on: [postgres], environment: SPRING_DATASOURCE_URL / USERNAME / PASSWORD / MIG_GLOBAL_SCHEMA / MIG_TENANT_SCHEMA_PREFIX from .env, command: --all

## Resultado esperado

`docker-compose up migrations` runs the job, applies V0001-V0005 (or no-op if already applied), and exits 0. The container status is "Exited (0)". Injecting a bad script causes "Exited (2)".

## Criterios de aceite
- [ ] AC-1 docker-compose service for migrations has restart:no (not unless-stopped or always)
- [ ] AC-2 docker-compose up migrations exits with the job's exit code (0 for clean run, 2 for failure)
- [ ] AC-3 depends_on: [postgres] ensures PostgreSQL is reachable before the job starts
- [ ] AC-4 Dockerfile produces a runnable image that executes `java -jar neuroassist-niv-migrations.jar --all` by default

## Contexto

BDD scaffold that wires the Cucumber test runner with the Spring Boot test context. This
issue creates the structural scaffold (runner, context, step stubs, shared steps for JWT
token building); actual scenario implementations are filled by `/be-implement` per priority.

Key rules:
- `CucumberIT` goes in the **`integrationTest`** source set (not in `test`) — it starts the
  full Spring context and requires running services; the `test` task excludes `*IT.class`
  (ACS-001, D-636 fix).
- BDD step stub bodies use `throw new PendingException()` only — no `// TODO:` comment
  (pitfall `bdd:step-stub:todo-comment-duplicates-pending-exception`).
- `SharedSteps.buildCaregiverToken(role)` and `SharedSteps.buildPatientSessionToken()`
  source their authority strings from `RoleAuthorityPolicy` constants (pitfall
  `bdd-scaffold:authority-strings:controller-preauthorize-mismatch-roleauthoritypolicy`).
- 46 scenarios from SPEC-08 (feature files already created in ACS M3 — tests/cucumber/).
  This issue connects them to the step defs; it does NOT re-write the .feature files.

# MIG-022 -- CI gate — assert spring.flyway.enabled=false in all business services + no flat V1 in MIG aggregation locations (SPEC-10, INV-MIG-7)

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

MIG is the sole Flyway runner (INV-MIG-7). A business service accidentally re-enabling Flyway or its scaffold-generated V1__create_initial_schema.sql leaking into MIG's aggregation locations would cause silent schema drift. This CI gate fails the build on any such violation. It is owned by the MIG module because MIG is the invariant enforcer.

## Spec de referencia
- SPEC-10 (CI gate, INV-MIG-7, ADR-003)
- contracts/integration-contracts.md §4

## Escopo
- `services/neuroassist-niv-migrations/gradle/tasks/CiGateTask.kt` (or a Gradle task in build.gradle.kts) — task `migrationCiGate`: (1) scans backend/services/*/src/main/resources/application*.yml files for `spring.flyway.enabled:` not equal to `false`; (2) scans services/neuroassist-niv-migrations/src/main/resources/db/migration/global/ and .../tenant/ for any file matching `V1__*.sql`; fails build with a clear message on any violation
- Wire `migrationCiGate` task as a dependency of the `check` lifecycle task

## Resultado esperado

`./gradlew migrationCiGate` passes on the current codebase (all business services have spring.flyway.enabled=false; no V1 flat script in MIG locations). Injecting a V1 flat script into the global location causes the task to fail with a clear error.

## Criterios de aceite
- [ ] AC-1 `./gradlew migrationCiGate` exits 0 on the current codebase
- [ ] AC-2 Adding spring.flyway.enabled: true to any business service's application.yml causes the gate to exit non-zero with that service named
- [ ] AC-3 Adding V1__create_initial_schema.sql to db/migration/global/ causes the gate to exit non-zero naming the offending file
- [ ] AC-4 Gate is run as part of `./gradlew check`

## Dependencias
- MIG-012 (Gradle aggregation task defines the locations to check, precede)

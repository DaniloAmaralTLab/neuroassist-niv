## Contexto

Create the Gradle subproject and Spring Boot bootstrap for the centralized Flyway migrator job. MIG is a non-web CommandLineRunner: no HTTP port, no Eureka client, no broker. It is the only service that runs Flyway; every other service must keep spring.flyway.enabled=false (ADR-002, INV-MIG-7).

## Spec de referencia
- SPEC-01 (CLI runner contract, no HTTP port)
- SPEC-02 (orchestration, spring.flyway.enabled=false)

## Escopo
- `services/neuroassist-niv-migrations/build.gradle.kts` — Gradle subproject with Spring Boot plugin, Flyway dependency, integrationTest source set
- `services/neuroassist-niv-migrations/src/main/java/com/neuroassist/migrations/NeuroAssistMigrationsApplication.java` — @SpringBootApplication entry point
- `services/neuroassist-niv-migrations/src/main/resources/application.yml` — spring.main.web-application-type=none, spring.flyway.enabled=false, no server.port
- `services/neuroassist-niv-migrations/src/main/resources/application-local.yml` — local datasource defaults from setup-local.md

## Resultado esperado

A Gradle subproject that compiles and boots with `./gradlew :services:neuroassist-niv-migrations:bootRun --args=""` (no mode), prints a usage error, and exits 1 without touching any database schema.

## Criterios de aceite
- [ ] AC-1 `./gradlew :services:neuroassist-niv-migrations:compileJava` exits 0
- [ ] AC-2 `spring.main.web-application-type: none` is set; no `server.port` present in application.yml
- [ ] AC-3 `spring.flyway.enabled: false` is set so Spring Boot auto-configuration does not run Flyway
- [ ] AC-4 Starting the app with no arguments prints usage and exits 1 (exit code verified in a smoke test)

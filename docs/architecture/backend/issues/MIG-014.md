# MIG-014 -- SchemaAdmin.createSchemaIfAbsent() — idempotent non-transactional CREATE SCHEMA (SPEC-03, INV-MIG-6)

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

Provisioning a new tenant requires CREATE SCHEMA t_<tenantId> before Flyway can run against it. This DDL must NOT be in any @Transactional scope that also contains a Flyway invocation (deadlock risk, INV-MIG-6, doc 06 R5). createSchemaIfAbsent is idempotent: if t_<tenantId> already exists the method returns without error (--provision-tenant is re-runnable). The tenantId-to-schema-name derivation is exactly `t_<tenantId>` (A4, doc 06 R8) — consistent with every other point that references this convention.

## Spec de referencia
- SPEC-03 (--provision-tenant path, idempotent schema creation, INV-MIG-6)

## Escopo
- `services/neuroassist-niv-migrations/src/main/java/com/neuroassist/migrations/infrastructure/SchemaAdmin.java` — extend with createSchemaIfAbsent(String tenantId): validate tenantId (reject if derived schema name is not a valid identifier); execute `CREATE SCHEMA IF NOT EXISTS t_<tenantId>` via admin JDBC; no @Transactional
- Update `services/neuroassist-niv-migrations/src/test/java/com/neuroassist/migrations/infrastructure/SchemaAdminTest.java`

## Resultado esperado

SchemaAdmin.createSchemaIfAbsent("unitC") creates t_unitC on a fresh DB. Calling twice does not throw. Calling with tenantId "bad name!" (invalid schema char) throws IllegalArgumentException before touching the DB.

- [ ] AC-3 tenantId with characters that would yield an invalid Postgres identifier is rejected with a clear exception before any DB statement
- [ ] AC-4 Method is NOT annotated @Transactional and does not call any @Transactional method

# GWY-009 -- In-memory rate limiting — login bucket (POST /acs/auth/login) + pairing bucket (POST /edge/devices/pair), 429, per-IP key (ADR-005)

**Status:** INTACT -- gerado 2026-11-22
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/5 itens

## Contexto

Protects two high-value public endpoints against brute-force: login (credential stuffing
risk) and device pairing (pairing-claim replay risk). Rate limiting uses in-memory
per-instance token buckets — no Redis in the MVP (ADR-005, single-instance assumption A4).
Keyed primarily by client IP; a secondary key (username prefix for login, pairing-code
prefix for pairing) reduces over-throttling under shared NAT. Thresholds (`capacity`,
`refill-per-minute`) are **configuration** (Gap G4 — values are proposals, mechanism
is fixed). No other route is rate-limited at the edge in this phase. Returns 429 with a
PHI-free ProblemDetail body (coordinates with GWY-011) when the bucket is exhausted.

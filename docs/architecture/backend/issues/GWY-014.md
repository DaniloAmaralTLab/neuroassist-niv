# GWY-014 -- Idempotent-only retry — GET only via retry filter, never login/pairing/event-report POST (ADR-006, Risk R8)

## Contexto

A blanket retry policy would double-issue a login (double-auth), a pairing claim
(double-pair), or an event report (duplicate event in HIST). Retry must be restricted
to idempotent verbs only (ADR-006, Risk R8). Spring Cloud Gateway's `Retry` filter
supports a `methods` list; set it to `GET` only. The retry filter must be applied to
all routes but the exclusion on `POST/PATCH/DELETE` enforced at the config level —
no special-casing per route in code. Routes for login and pairing are public paths;
even if accidentally retried in config, the rate-limit bucket (GWY-009) provides a
second line of defence.

# Module Pattern (NeuroAssist NIV Frontend)

> **Status:** mandatory standard. Canonical source for the structure and naming of an FE module.

## Vocabulary

The frontend unit is the **MODULE** (e.g.: GWY, REG, MIG, GEST, EVNT, PAT, ACS, HIST, DASH, EDGE, CONV, TRN).
The npm scope is **`@neuroassist`** and the skeleton is generated by the local Nx plugin
**`@neuroassist/internal:module`**. Here **only `module` exists** as a unit — no
alternative concepts inherited from a template project.

| Concept | Canonical form |
|---|---|
| unit | **module** (`<module>`, ex.: `gwy`) |
| generator | **`@neuroassist/internal:module`** |
| shared libs | **`@neuroassist/shared/*`** |
| module entry | `libs/<module>/shell-entry` → importPath **`@neuroassist/<module>`** (ADR-006) |
| entry files | `<module>.{module,contract,routes,permission-map,feature-flags,bootstrap,nav.config,descriptor}.ts` |
| Shell registration | **`module-descriptors.ts`** (`<MODULE>_MODULE_DESCRIPTOR`) |
| field in generator-config | **`module:`** |

> In prose, use "**module**".

## Canonical structure of a module (module slicing)

```
libs/<module>/shell-entry/   (type:app)         # ENTRY as a library — importPath @neuroassist/<module> (ADR-006)
└── src/lib/
    ├── <module>.module.ts                      # the module's only NgModule
    ├── <module>.contract.ts                    # MODULE_KEY + ModuleMenuMetadata + permissions + flags
    ├── <module>.bootstrap.ts                   # init/destroy lifecycle
    ├── <module>.routes.ts                      # <MODULE>_ROUTES[]
    ├── <module>.permission-map.ts              # ModulePermissionMap
    ├── <module>.feature-flags.ts               # ModuleFeatureFlags (defaultState)
    ├── <module>.nav.config.ts                  # navigation/breadcrumb
    └── <module>.descriptor.ts                  # <MODULE>_MODULE_DESCRIPTOR (consumed by the Shell)

apps/<module>/             (type:app)           # thin host: app.routes loads @neuroassist/<module>
libs/<module>/                                  # module libs
├── access/            (type:domain)            # specific guards
├── data-access/       (type:data-access)       # *ApiService + facades signals
├── feature-<X>/       (type:feature)           # one per feature
├── integration/       (type:domain)            # <Module>ShellIntegrationService
├── navigation/        (type:domain)            # breadcrumbs/menu state
├── ui/                (type:ui, optional)       # local components
└── styles/            (type:ui, optional)       # module CSS (Tailwind utilities + tokens; no token SCSS)

apps/<module>-e2e/                              # Playwright (specs of the .feature files)
```

> **Why the entry is a library (ADR-006):** the Shell needs to import `<module>.descriptor.ts`
> to register the module, but Nx apps do not import other apps. So the entry lives in a lib with
> `importPath @neuroassist/<module>`; `apps/<module>` is just a thin host (`nx serve/build`
> + e2e base).

Nx tags: `scope:<module>` + `type:{feature|data-access|domain|ui}` (see `nx-boundaries.md`).
Rules: standalone + OnPush + Signals; `NgModule` **only** in `<module>.module.ts`; a module only
imports `scope:<module>` + `scope:shared`. HTTP via `@neuroassist/shared/access-http-base`
(interceptor injects `X-Tenant-Id`).

## The `@neuroassist/internal:module` generator

- **Local Nx plugin:** `frontend/libs/internal-nx-plugin` (npm `@neuroassist/internal`).
- **Invocation:** `npx nx g @neuroassist/internal:module --name=<module>`.
- **Document-driven:** reads
  `docs/architecture/frontend/modules/<module>/frontend/frontend-spec/generator-config.yml`
  and derives: entry lib `libs/<module>/shell-entry` (`@neuroassist/<module>`) + module
  libs + host `apps/<module>` + `apps/<module>-e2e`. Idempotent. The Shell registers the module
  by importing `@neuroassist/<module>`.
- **Post-scaffold gates:** `nx lint <module>` → `nx test <module>` → `nx build <module>`.

> Precondition: the **shared libs** (`@neuroassist/shared/*`) and the **App Shell**
> (`neuroassist-niv-web`) must exist before scaffolding any module — otherwise the generated
> code does not compile (unresolved imports).

## Relationship with the backend

The BE uses **Python scripts** (`be-module-generator.py`) for the same role; the FE uses a **local Nx
plugin** (idiomatic to the Angular/Nx workspace). Both are document-driven from the module's
`generator-config.yml`. The conceptual unit ("MODULE") and the issue prefix are
shared.

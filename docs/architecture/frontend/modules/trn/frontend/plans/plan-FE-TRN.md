## 1. Module summary

TRN (AI-Assisted Training) is a collaborative, write-heavy authoring surface where a caregiver and a patient/guardian work together to build a personalized AAC voice library using Claude-mediated LLM proposals. The module is characterised by:

- **Dual authorization:** every proposal requires both caregiver approval and patient/guardian assent before publication; both roles use a single caregiver-session identity (ADR-005 amendment; no patient-session token).
- **BE-mediated LLM:** the caregiver sends dialog turns to the backend; the backend orchestrates Claude; the frontend receives proposals reactively. The frontend never generates or fabricates proposals.
- **Fail-safe audio preview:** a three-step cascade (BE-served clip → device TTS → text-only) ensures preview is never silent.
- **Server-authoritative publication:** publication is never optimistic; `pending-synth` is a state badge, not an error. The 202/polling loop in the adapter is the source of truth.
- **Host-portable assent surface:** `PatientAssentPageComponent` supports three input channels (touch, gesture via NAVIGATION_INTENT_PORT, switch-scan) for ALS/MND accessibility.

The five bounded-context ports are: `TrainingSession`, `Proposal`, `Consent`, `Publication`, `Content`. All share the base URL `${ACCESS_HTTP_BASE}/trn`.
